PyTorch Master Course — Chapter 6

Real Linux Log Ingestion, Parsing, Feature Engineering, Dataset Creation and DataLoader

Level: beginner → production-aware intermediate. Platform: Debian/Ubuntu Linux, Python 3.10+, CPU sufficient. Outcome: Convert SSH authentication events from journalctl -o json into numerical, time-windowed observations ready for PyTorch.

Security and scientific limitation: This chapter produces unlabeled feature records. It does not invent ground-truth attack labels. Real model evaluation requires independently verified labels, representative normal traffic, and a time-separated test set. Never treat high failure counts as proof of an attack.

6.1 Why a log pipeline is part of machine learning

A neural network does not consume the meaning of Failed password for root automatically. The pipeline transforms raw evidence into numeric measurements. Data quality, consistent time handling, and feature reproducibility matter as much as model architecture.

Linux hosts → journald → JSON export → event parser → normalization
→ group by source IP + 5-minute UTC bucket → numeric feature CSV
→ validated feature order → train-only scaler → PyTorch DataLoader
→ trained model → SOC investigation

Key concepts

  • Event: One journal record, e.g. one failed SSH login.
  • Observation: One aggregated IP/time-window row, potentially containing many events.
  • Feature: Numeric property such as failed logins or username diversity.
  • Label: Externally verified outcome, e.g. suspicious vs normal. Not produced by this parser.
  • Ingestion: Reading records from the source.
  • Normalization: Mapping varied messages to a stable event schema.
  • Aggregation: Summarizing events within a defined time window.
  • Data leakage: Accidentally letting information from validation/test periods influence training.
  • Idempotence: Re-running ingestion without unintentionally duplicating the same source events.

6.2 Locate SSH logs on Debian

Run on the Linux host, not inside the Python virtual environment:

sudo systemctl status ssh
sudo journalctl -u ssh.service --since '1 hour ago' --no-pager
sudo journalctl -o json -u ssh.service -n 3 --no-pager
sudo test -f /var/log/auth.log && sudo tail -n 5 /var/log/auth.log

auth.log depends on rsyslog and distribution configuration; it may not exist. A journal unit filter is not guaranteed to include all sshd events on every system. Verify the returned SYSLOG_IDENTIFIER, _COMM, _SYSTEMD_UNIT, and MESSAGE fields before building a collector. On some systems sshd.service is the unit name.

Production ingestion alternatives

Method Strength Tradeoff
journalctl -o json Structured timestamps and metadata Permissions, retention, filtering
auth.log / secure Familiar file-based collection Rotation, timestamp year ambiguity
Filebeat / Fluent Bit Shipping and buffering Operational components and configuration
journald API Cursor-based processing Library dependencies and deployment complexity

For a one-time lab, export a bounded journal snapshot:

sudo journalctl -u ssh.service --since '24 hours ago' -o json --no-pager > ssh-journal.jsonl
chmod 600 ssh-journal.jsonl

The file may contain usernames, source addresses and other sensitive metadata. Restrict permissions, retention and access. In production, use a dedicated least-privilege collection identity rather than making the model service root.

6.3 Why journal JSON is better than parsing the displayed timestamp

Traditional syslog lines can look like Oct 08 10:15:01 and omit the year and timezone. Journal JSON provides __REALTIME_TIMESTAMP, a Unix epoch timestamp in microseconds, which we can convert to timezone-aware UTC. It avoids guessing the year. Note that wall clocks can still jump due to clock corrections; use a sound time synchronization strategy and account for late events.

Example (documentation IP addresses):

{"__REALTIME_TIMESTAMP":"1791454501000000","SYSLOG_IDENTIFIER":"sshd","MESSAGE":"Failed password for root from 192.0.2.10 port 51001 ssh2"}

6.5 Complete runnable parser and feature builder — ingest.py

The parser supports Failed password and Accepted password messages, including invalid user, IPv4 and IPv6. Other authentication mechanisms and message formats require explicit extension; unmatched messages are counted, not silently assumed to be normal.

#!/usr/bin/env python3
"""Convert SSH journald JSON lines into unlabeled 5-minute feature windows."""
import argparse
import csv
import ipaddress
import json
import re
from collections import defaultdict
from datetime import datetime, timezone
from pathlib import Path

# Match SSH password authentication messages; named groups clarify extraction.
AUTH_RE = re.compile(
    r"^(?P<result>Failed|Accepted) password for "
    r"(?:(?:invalid user) )?"
    r"(?P<username>\S+) from (?P<ip>\S+) port (?P<port>\d+) ssh2(?:\b|$)"
)
FEATURE_NAMES = [
    "failed_count", "success_count", "unique_users",
    "failure_ratio", "off_hours", "attempts_per_minute",
]
WINDOW_SECONDS = 300


def parse_event(line):
    """Return normalized event or None if unsupported/invalid."""
    try:
        record = json.loads(line)
        if record.get("SYSLOG_IDENTIFIER") not in ("sshd", "ssh"):
            return None
        match = AUTH_RE.search(record.get("MESSAGE", ""))
        if not match:
            return None
        address = str(ipaddress.ip_address(match.group("ip")))
        micros = int(record["__REALTIME_TIMESTAMP"])
        if micros < 0:
            return None
        return {
            "timestamp_us": micros,
            "ip": address,
            "username": match.group("username"),
            "result": match.group("result").lower(),
        }
    except (ValueError, TypeError, KeyError, json.JSONDecodeError):
        return None


def aggregate(events):
    """Group by source address and non-overlapping 5-minute UTC windows."""
    buckets = defaultdict(list)
    for event in events:
        seconds = event["timestamp_us"] // 1_000_000
        bucket_start = (seconds // WINDOW_SECONDS) * WINDOW_SECONDS
        buckets[(event["ip"], bucket_start)].append(event)

    rows = []
    for (ip, start), group in sorted(buckets.items(), key=lambda kv: (kv[0][1], kv[0][0])):
        failures = sum(e["result"] == "failed" for e in group)
        successes = sum(e["result"] == "accepted" for e in group)
        count = failures + successes
        hour_utc = datetime.fromtimestamp(start, tz=timezone.utc).hour
        rows.append({
            "source_ip": ip,
            "window_start_utc": datetime.fromtimestamp(start, tz=timezone.utc).isoformat(),
            "failed_count": failures,
            "success_count": successes,
            "unique_users": len({e["username"] for e in group}),
            "failure_ratio": round(failures / count, 6),
            # Illustrative UTC off-hours only. Production should use host/business timezone.
            "off_hours": int(hour_utc < 6 or hour_utc >= 22),
            "attempts_per_minute": round(count / (WINDOW_SECONDS / 60), 6),
        })
    return rows


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--input", required=True, type=Path)
    parser.add_argument("--output", default=Path("ssh_features.csv"), type=Path)
    args = parser.parse_args()
    events = []
    total = 0
    with args.input.open("r", encoding="utf-8") as stream:
        for line in stream:
            total += 1
            event = parse_event(line)
            if event is not None:
                events.append(event)
    rows = aggregate(events)
    with args.output.open("w", newline="", encoding="utf-8") as stream:
        writer = csv.DictWriter(stream, fieldnames=["source_ip", "window_start_utc", *FEATURE_NAMES])
        writer.writeheader()
        writer.writerows(rows)
    print(f"Read {total} records; parsed {len(events)} events; produced {len(rows)} windows")
    print(f"Saved {args.output}")


if __name__ == "__main__":
    main()

Line-by-line conceptual explanation

  1. argparse accepts paths from the command line so source files are not hardcoded.
  2. csv writes an interoperable feature dataset; json parses journal records.
  3. ipaddress.ip_address() validates both IPv4 and IPv6 and canonicalizes address text.
  4. re.compile() prepares a reusable pattern; named groups extract the outcome, username, IP and port.
  5. FEATURE_NAMES is the schema contract. The neural network must consume these six features in exactly this order.
  6. parse_event() converts each JSON record into a normalized dictionary. None means unsupported or malformed; it does not mean a legitimate login.
  7. int(record["__REALTIME_TIMESTAMP"]) reads microseconds; dividing by 1_000_000 converts to Unix seconds.
  8. defaultdict(list) groups normalized events into windows without pre-creating each key.
  9. seconds // 300 * 300 rounds a timestamp down to the beginning of its five-minute UTC bucket.
  10. sum(condition for e in group) counts matches because Python booleans behave as 1 and 0 in arithmetic.
  11. A set {e["username"] for e in group} measures username diversity without counting duplicates.
  12. failure_ratio divides failures by all parsed password authentication events in that window; the denominator cannot be zero for a nonempty group.
  13. off_hours is a simplistic UTC flag for demonstration. It must be configured for the host or organization before operational use.
  14. attempts_per_minute uses a fixed five-minute denominator. It measures event frequency across the window, not the instantaneous peak rate.
  15. csv.DictWriter preserves the field names and their order; newline="" prevents extra blank lines on some platforms.
  16. The final counters make parser coverage visible. Investigate unexpected drops in the parsed/total ratio.

Important production gaps

The parser deliberately handles only password authentication messages. Modern SSH environments may use public-key authentication, PAM, keyboard-interactive, MFA, Invalid user messages, connection resets, or vendor-specific log formats. Expand supported event types with fixtures and tests before relying on its coverage. Large inputs should be streamed into incremental aggregates rather than accumulating all events in memory. A production collector also needs durable cursors, rotation/retention handling, deduplication, late-arrival policy, and bounded retries.

6.6 Create sample journal data without SSH attacks

Use this small generator to create safe synthetic log events. No real login attempts are performed:

# save as make_sample.py
import json
from datetime import datetime, timezone, timedelta

start = datetime(2026, 10, 8, 10, 0, tzinfo=timezone.utc)
messages = [
    "Failed password for root from 192.0.2.10 port 50001 ssh2",
    "Failed password for invalid user test from 192.0.2.10 port 50002 ssh2",
    "Accepted password for alice from 198.51.100.7 port 50003 ssh2",
    "Failed password for root from 192.0.2.10 port 50004 ssh2",
]
with open("ssh-journal.jsonl", "w", encoding="utf-8") as output:
    for i, message in enumerate(messages):
        timestamp = start + timedelta(seconds=i * 30)
        output.write(json.dumps({
            "SYSLOG_IDENTIFIER": "sshd",
            "__REALTIME_TIMESTAMP": str(int(timestamp.timestamp() * 1_000_000)),
            "MESSAGE": message,
        }) + "\n")

Run:

python make_sample.py
python ingest.py --input ssh-journal.jsonl --output ssh_features.csv
cat ssh_features.csv

Expected terminal summary:

Read 4 records; parsed 4 events; produced 2 windows
Saved ssh_features.csv

The two rows correspond to source 192.0.2.10 (three failures, two distinct usernames) and 198.51.100.7 (one success). Both belong to the 10:00–10:05 UTC window. Their respective attempts/minute values are 0.6 and 0.2.

6.7 Convert CSV into PyTorch tensors — prepare_torch.py

import pandas as pd
import torch
from torch.utils.data import TensorDataset, DataLoader

FEATURE_NAMES = [
    "failed_count", "success_count", "unique_users",
    "failure_ratio", "off_hours", "attempts_per_minute",
]

df = pd.read_csv("ssh_features.csv")
if df.empty:
    raise ValueError("No supported SSH events found")

X = torch.tensor(df[FEATURE_NAMES].to_numpy(dtype="float32"))
assert X.ndim == 2 and X.shape[1] == 6
assert torch.isfinite(X).all(), "Missing or non-finite features"

dataset = TensorDataset(X)
loader = DataLoader(dataset, batch_size=32, shuffle=False)

for (batch_x,) in loader:
    print("Batch shape:", tuple(batch_x.shape))
    print(batch_x)

Run python prepare_torch.py. For the four sample events, the batch shape is (2, 6): two source-IP windows, six features each. TensorDataset exposes tensor rows as dataset items; DataLoader assembles batches. There are no labels, so this dataset is suitable for inference or further labeling, not supervised training.

Why not fit a scaler to this entire dataset?

For supervised learning, split observations first. Fit StandardScaler only on the training split, then reuse its saved mean and variance for validation, test and inference. Fitting it on the whole dataset leaks statistical information from the future. For log events, use time-based splits and consider separating related IPs/sessions to avoid inflated scores. Never fit a fresh scaler separately in production.

Why feature engineering can fail

  • High cardinality: Usernames and IPs should not be assigned arbitrary numerical IDs as if they have a meaningful numeric ordering.
  • Skewed counts: Failed-login counts may be heavy-tailed; log1p transformations can help, if applied consistently.
  • Missing data: No journal entries may mean missing collection rather than zero authentication attempts.
  • Clock skew: Host clock drift and ingestion delays can place events into the wrong windows.
  • Class imbalance: Real incidents may be rare; accuracy alone can be misleading.
  • Label contamination: Treating a heuristic threshold as ground truth merely trains the network to mimic that heuristic.

6.8 How to obtain trustworthy labels

Collect analyst-reviewed cases, authorized test scenarios and well-documented incident records. Preserve the reason, provenance, event time and review status for each label. Separate known malicious, known benign and unknown cases; do not automatically label unknown traffic benign. Use an explicit labeling policy, inter-analyst checks, and a held-out future-period evaluation dataset.

Useful metrics include precision, recall, PR-AUC, false positives per host-day, detection latency and alert volume. Tune the decision threshold on validation data based on the cost of missed incidents and analyst workload, not on the test set.

6.9 Production scenarios and troubleshooting

Scenario A — No auth.log file: Check journalctl, rsyslog installation/configuration, service name and journal retention. Do not create an empty file and assume no events occurred.

Scenario B — CSV contains zero rows: Check JSON export fields and SYSLOG_IDENTIFIER; inspect representative MESSAGE values. SSH may use sshd under a different unit or non-password authentication.

Scenario C — Duplicate alerts after collector restart: Persist the journal cursor and processed event identity. Deduplicate on stable event identity and source metadata, not on IP alone.

Scenario D — Memory usage rises on a busy bastion: The lab code accumulates all events and buckets. Stream batches, flush closed windows and apply backpressure. Avoid unbounded dictionaries.

Scenario E — Off-hours alerts fire during business hours: UTC was used for the demonstration. Define the relevant local timezone and daylight-saving rules, and decide whether off-hours means host-local or user-local.

Scenario F — Training accuracy is 99% but SOC receives poor alerts: Check class imbalance, temporal leakage, threshold selection, precision-recall and data drift. Evaluate on a future time period and report absolute false-positive volume.

Scenario G — Training model has six inputs but API expects five: Validate the feature schema at startup, store feature order and preprocessing metadata alongside model weights, and fail closed on incompatible versions.

6.10 Unit tests — test_ingest.py

import json
import unittest
from ingest import parse_event, aggregate


def record(message, micros=1791453600000000):
    return json.dumps({
        "SYSLOG_IDENTIFIER": "sshd",
        "__REALTIME_TIMESTAMP": str(micros),
        "MESSAGE": message,
    })


class IngestTests(unittest.TestCase):
    def test_failed_password(self):
        event = parse_event(record(
            "Failed password for invalid user bob from 192.0.2.10 port 50001 ssh2"
        ))
        self.assertEqual(event["result"], "failed")
        self.assertEqual(event["username"], "bob")

    def test_invalid_ip_rejected(self):
        event = parse_event(record(
            "Failed password for root from not_an_ip port 50001 ssh2"
        ))
        self.assertIsNone(event)

    def test_aggregation(self):
        e1 = parse_event(record("Failed password for root from 192.0.2.10 port 50001 ssh2"))
        e2 = parse_event(record("Accepted password for alice from 192.0.2.10 port 50002 ssh2"))
        rows = aggregate([e1, e2])
        self.assertEqual(len(rows), 1)
        self.assertEqual(rows[0]["failed_count"], 1)
        self.assertEqual(rows[0]["success_count"], 1)
        self.assertEqual(rows[0]["failure_ratio"], 0.5)


if __name__ == "__main__":
    unittest.main()

python -m unittest -v test_ingest.py

Expected result: three tests pass.

6.11 Interview questions and model answers

Q1. Why use event-time rather than ingestion-time windows? Event time represents when authentication occurred. Ingestion time can be delayed by networking or collectors, distorting attack sequences. Late arrivals need a documented handling policy.

Q2. What is a watermark? In stream processing, a watermark expresses progress in event time and helps determine when a window is sufficiently complete despite late data.

Q3. Why group by source IP? It is a useful initial behavioral key, but NAT, proxies, IPv6 privacy addresses and distributed attacks limit its reliability. More advanced detectors use multiple entity relationships.

Q4. What is a feature schema? A versioned contract specifying feature names, order, types, transformations and missing-value behavior. Mismatched schemas cause unreliable inference.

Q5. What is the difference between a parser and a model? The parser extracts and normalizes evidence; the model learns statistical relationships between numerical inputs and outcomes.

Q6. Why is DataLoader useful? It batches examples and can shuffle or parallelize loading for training, reducing the need to load every training example into accelerator memory at once.

Q7. Why is random train/test splitting risky for security logs? Adjacent events, the same campaigns and the same entities can appear in both sets. Time-separated validation better approximates future deployment.

Q8. How do you avoid duplicate log processing? Use stable event identities or journal cursors, checkpoint progress and make downstream writes idempotent.

Q9. Can you label all windows with >10 failures as attacks? Not as verified ground truth. That creates heuristic labels; the model may only reproduce the threshold and miss other attack patterns.

Q10. Why is 99% accuracy sometimes poor? If only 1% of windows are attacks, a model predicting 'normal' for everything achieves 99% accuracy but detects no attacks.

Q11. What is training-serving skew? Differences in feature computation or preprocessing between training and production inference, which can silently degrade model behavior.

Q12. What is data drift? A change in the statistical distribution of incoming features; it may or may not reduce predictive quality. Monitor both feature distributions and labeled outcomes.

6.12 Exercises
