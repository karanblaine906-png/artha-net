PART 0 — HOW TO LEARN LIKE AN ENGINEER

Lesson 0 — What are we building, and why these three tools?

Mental model

Imagine a school with three specialist teachers:

  • C++ teaches precise control of memory, performance, data structures and compiled programs. It's the workshop where you learn what software does close to the machine.
  • scikit-learn is a toolbox for classical machine learning: logistic regression, trees, random forests, clustering, feature preprocessing and robust model evaluation. Mostly NumPy arrays and Python interfaces.
  • PyTorch is a deep-learning tool where you manipulate tensors and train neural networks using automatically computed gradients.

No, C++ is not a prerequisite for PyTorch. Python is the direct prerequisite. We study C++ because you explicitly want it and because its memory/performance ideas make you a stronger engineer. These are different tools, not interchangeable replacements.

The software-to-AI workflow

Question → Data → Clean/validate → Split → Model → Train
       → Evaluate → Debug → Package → Deploy → Monitor

A 98% accuracy printed in a notebook is not proof of a good model. What if 99% of the data belongs to one class? What if training leaked test information? What if production inputs differ? The job of an engineer is to ask these questions.

The universal 6-step debugging habit

  1. Reproduce: provide exact input, command, error and version.
  2. Reduce: shrink the failing case to 3–10 lines.
  3. Observe: read traceback/compiler diagnostic, inspect shapes/types/values.
  4. Hypothesize: one explanation, not ten random changes.
  5. Test: change one variable and rerun a targeted test.
  6. Prevent: add a regression test and write a 2-line incident note.

Interview warmup: Difference between an algorithm, program, ML model and trained weights? An algorithm is a method; a program implements instructions; a model describes a function or structure; weights are learned numeric parameters within a model.

Lesson 1 — Linux lab setup and command-line confidence

Why isolated environments?

Think of a Python virtual environment as a separate school bag. Each project carries its own package versions, without mixing them into system Python. Debian's OS package manager and pip should not fight for the same files.

sudo apt update
sudo apt install -y build-essential gdb cmake python3 python3-venv python3-pip
mkdir ai-school && cd ai-school
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
python -m pip install numpy scikit-learn pandas matplotlib pytest

For PyTorch, use the official CPU selector at https://pytorch.org/get-started/locally/ when you reach Lesson 28. Python compatibility and wheel availability vary by release. You don't need CUDA on an 8 GB CPU-only machine.

g++ --version
python --version
python -c 'import sklearn; print(sklearn.__version__)'

Debug: externally-managed-environment means you tried installing into system Python; create and activate .venv. ModuleNotFoundError means wrong environment or package not installed. Check which python and python -m pip show scikit-learn.

Homework: Make notes/error-log.md with columns date, command, error, root cause and fix. Learn pwd, ls, cd, mkdir, cat, grep, head, top and free -h.

PART I — C++ FROM ZERO TO PROFESSIONAL FOUNDATIONS

Lesson 2 — Your first compiled program

Think of source code as a recipe; a compiler turns it into a machine-readable executable. The OS runs that executable. Compilation happens before running; that is a major difference from the normal Python workflow.

#include <iostream>
int main() {
    std::cout << "Hello, engineer!\n";
    return 0;
}

#include makes declarations available. int main() is the entry point. {} encloses a code block. std::cout is a stream sending characters to standard output. ; finishes a statement. \n represents a newline; return 0 signals successful termination.

g++ -std=c++20 -Wall -Wextra -Wpedantic -g hello.cpp -o hello
./hello

-Wall -Wextra enable warnings; -g embeds debug symbols; -std=c++20 chooses a language standard.

Run: cpp/01_hello.cpp. Change the string and predict output.

Debug: error: expected ';' often means punctuation missing above the indicated line. undefined reference to main means no entry point was linked. ./hello: No such file means compile failed or wrong directory.

Interview: What is compile-time vs runtime error? Compile-time means translation fails; runtime means an already-built program encounters a failure or incorrect behavior.

Lesson 3 — Variables, types, conversions and operators

A variable is a named storage location with a type. int stores whole numbers, double floating-point values, bool true/false, char one character, std::string text. Types control which operations make sense and how values are represented.

int apples = 7;
int children = 2;
double wrong = apples / children;            // 3.0: integer division happened first
// double correct = static_cast<double>(apples) / children; // 3.5

Type conversion is a major source of silent bugs. Operator precedence also matters: a + b * c evaluates multiplication first. Integers have finite ranges: overflowing signed integers is undefined behavior. Prefer appropriate types and explicit casts; never assume arbitrary sizes.

Practice: Temperature C→F, compound interest for one year, swap two values, compute rectangle perimeter, grade percentage. Test zero denominator and negative inputs.

Debug: If 5/2 prints 2, neither variable is floating-point. Cast one operand before division.

Interview: Difference between = and ==? Assignment changes a value; comparison produces a boolean.

Lesson 4 — Conditions and loops

An if statement chooses a route. A for loop repeats for a known iteration pattern; while repeats while a condition holds. break exits; continue skips to next iteration.

int sum = 0;
for (int n = 1; n <= 10; ++n) {
    if (n % 2 == 0) sum += n;
}
// 2 + 4 + 6 + 8 + 10 = 30

The loop invariant is: before each iteration, sum is the total of even numbers processed so far. Thinking in invariants helps you prove correctness rather than guessing.

Run: cpp/02_control_flow.cpp. Rewrite using while; add a negative-number check to a grading program.

Debug: for (int i=0; i<=v.size(); i++) often accesses one element too far. Valid indices go from 0 to size()-1; an empty list has no valid index.

Interview: for vs while? Both can express the same repetition; choose based on clarity and termination condition.

Lesson 5 — Functions, parameters, scope and references

Functions are named reusable operations. They keep code testable. Inputs are parameters, output is the return value. A function with one responsibility is easier to debug.

double average(double sum, int count) {
    if (count <= 0) throw std::invalid_argument("count must be positive");
    return sum / count;
}
  • Pass by value: copy value into parameter; edits do not affect caller.
  • Pass by reference int&: alias caller's variable; edits can affect caller.
  • Pass by const reference const std::vector<int>&: avoid copying a large object while forbidding mutation.
  • Scope: local names usually cease to exist when their block ends.

Run: cpp/03_functions.cpp. Add highest_score(const vector<int>&) and test empty input.

Debug: not declared in this scope: variable outside visibility; undefined reference: declaration was seen, but definition not linked. A reference bound to a destroyed object leads to undefined behavior.

Interview: Why use const & for a large object? Avoid potentially costly copy and express read-only intent.

Lesson 6 — Arrays, vectors and strings

A std::vector<T> is a dynamically sized sequence. std::string represents text. Use v.at(i) while learning: it performs bounds checking; v[i] does not.

std::vector<int> marks{80, 95, 72};
marks.push_back(88);
for (int mark : marks) std::cout << mark << ' ';

A vector has a size (existing elements) and capacity (allocated room). Expanding capacity may move elements and invalidate references, pointers and iterators. This is important later in real C++ code.

Run: cpp/04_vectors.cpp. Add median and range checks. Try passing an empty vector; observe intentional exception.

Debug: Segmentation faults or mysterious values can arise from out-of-range indices. Use .at, compiler warnings, sanitizers and the debugger; do not silently hide the problem.

Interview: Array vs vector? An array usually has fixed extent; vector manages resizable storage and its lifetime safely.

Lesson 7 — Memory, pointers and references

Computer memory can be imagined as numbered lockers. A pointer stores a memory address; dereferencing (*p) accesses the object there. A reference is another name for an existing object. A pointer may be nullptr and may be reassigned.

int value = 10;
int* address = &value;
*address = 20;       // value is now 20

Stack typically refers to automatic storage for local variables and call frames; heap colloquially refers to dynamic allocation. The standard describes storage durations; avoid believing the simplified diagrams are universal physical rules.

A dangling pointer points to an object whose lifetime has ended. Dereferencing it is undefined behavior, even when a program appears to work.

Practice: Trace the values of p, *p and value after each statement. Explain why returning a reference to a local variable is dangerous.

Debug: Never dereference a null pointer. Prefer references or smart pointers when raw pointers are unnecessary.

Interview: Pointer vs reference? A pointer holds an address and can be null; a reference is an alias bound during initialization and must refer to a valid object during use.

Lesson 8 — Classes, encapsulation and OOP

A class bundles data + behavior. private protects an object's invariants; public exposes supported operations. A constructor establishes valid initial state. const on a method promises not to mutate the object's externally observable state (subject to language nuances).

class Thermometer {
  double celsius_;
public:
  explicit Thermometer(double c) : celsius_(c) {}
  double fahrenheit() const { return celsius_ * 9.0 / 5.0 + 32; }
};

The four familiar OOP concepts: encapsulation, abstraction, inheritance, polymorphism. Do not use inheritance just because you can; often composition creates simpler systems.

Run: cpp/05_classes.cpp. Add a transfer method with tests for insufficient funds. This is a training example, not financial-grade software (floating-point currency is unsafe in production).

Debug: private within this context signals API boundary; do not make everything public to silence compiler. Add an appropriate method.

Interview: What is encapsulation? Restricting direct manipulation of internal state, maintaining invariants through controlled methods.

Lesson 9 — Ownership, RAII, exceptions and smart pointers

RAII means a resource's lifetime is tied to an object's lifetime. When an object goes out of scope, its destructor runs and releases owned resources. This helps manage files, mutexes and allocated memory even when exceptions occur.

auto sensor = std::make_unique<int>(42);
std::cout << *sensor << '\n';
// freed automatically when sensor's lifetime ends

std::unique_ptr<T> means one owning pointer; std::shared_ptr<T> supports shared ownership but adds cost and can leak through reference cycles. Prefer value types and unique_ptr by default, and shared ownership only when it's genuinely needed.

Run: cpp/06_raii.cpp. Predict lifetime of each object; contrast std::vector storage with raw new and delete.

Debug: double free/use-after-free are memory safety defects. Compile with sanitizers described in DEBUGGING_PLAYBOOK.md.

Interview: Why is RAII preferable to manual cleanup? It makes resource release deterministic as object lifetime ends, including exceptional exits.

Lesson 10 — STL containers, algorithms and complexity

STL standard library containers and algorithms save you from rewriting common operations. Typical choices:

Need Container Typical operation
Index by position vector v[i], amortized O(1) push_back
Key/value sorted map O(log n) lookup
Key/value hashed unordered_map Average O(1) lookup
Last-in-first-out stack push, top, pop
First-in-first-out queue push, front, pop

Big-O describes how resource usage grows with input. O(1) constant, O(log n) logarithmic, O(n) linear, O(n log n) common comparison sort, O(n²) quadratic. Big-O isn't the whole performance story: cache locality, allocations and real workloads matter.

Run: cpp/07_stl_algorithms.cpp. Compare linear search against binary_search on sorted input.

Debug: Calling binary_search on unsorted input breaks its precondition; results are unreliable.

Interview: Map vs unordered_map? Balanced-tree ordered keys and O(log n) operations versus hash-based average O(1) operations without key order guarantee.

Lesson 11 — Templates, generic algorithms and modern C++

A template is a recipe for code that works with multiple types. A compiler generates appropriate instantiations when needed.

template<class T>
T square(T value) { return value * value; }

Modern C++ ideas worth learning: auto type deduction, constexpr, range-based loops, move semantics, std::optional, lambdas and std::span (C++20). A move can transfer resources instead of copying; it is not a magical fast operation on every type.

Run: cpp/08_templates.cpp. Modify for empty input: throw an informative exception or return std::optional<T>.

Debug: Template errors can be verbose. Read the first substantive compiler error and identify the type that failed the required operation.

Interview: Why templates? Type-safe reuse without duplicating function logic for every type.

Lesson 12 — Files, parsing and input validation

Most real programs read outside data. Data is often dirty: missing fields, invalid integers, unexpected commas, extra whitespace. Validate early and fail clearly.

std::istringstream row("Ada,90");
std::string name, score;
std::getline(row, name, ',');
std::getline(row, score);

This is a toy CSV reader; production CSV must support escaped quotes, delimiters inside quoted fields and encoding. Never treat a demonstration parser as complete.

Run: cpp/09_files.cpp. Add a third row with not-a-number and see how std::stoi fails. Catch the exception at the program boundary and show a useful error.

Interview: Why validate at the boundary? Invalid external inputs should not corrupt the trusted core of an application.

Lesson 13 — DSA: two-sum, stacks, queues, complexity

Problem-solving template: explain brute force; derive more efficient approach; choose data structure; estimate complexity; write edge tests.

Two-sum: given numbers and target, return indices of two distinct elements whose sum equals target. Brute force nested loops O(n²). A hash map of previously seen values supports expected O(n) time and O(n) extra space.

Run: cpp/10_dsa.cpp. Test duplicate values, no solution, negatives and empty input. Be careful with integer overflow when calculating complements.

Further challenges: binary search O(log n), valid parentheses with stack O(n), BFS with queue O(V+E), DFS with recursion/stack, reverse linked list O(n), sliding-window maximum O(n) with deque, shortest path fundamentals, sorting algorithms and recursion.

Debug: A solution that passes a sample but fails empty or duplicate input is incomplete. Always write edge-case tests.

Interview: Why might unordered_map be O(n) worst-case? Hash collisions can degrade behavior; average assumptions depend on hashing and inputs.

Lesson 14 — Threads, tests, GDB, sanitizers and build systems

A race condition happens when program correctness depends on uncontrolled interleaving of threads. Two threads incrementing the same unprotected variable have a data race (undefined behavior in C++).

std::mutex mutex;
// inside concurrent worker:
std::lock_guard<std::mutex> guard(mutex);
++counter;

Run: cpp/11_threads.cpp and cpp/12_tests.cpp. Later learn std::atomic, deadlocks, condition variables and thread ownership.

GDB commands: gdb ./program, break main, run, next, step, print variable, bt, quit.

Debug builds:

g++ -std=c++20 -g -O1 -Wall -Wextra -fsanitize=address,undefined \
    -fno-omit-frame-pointer cpp/04_vectors.cpp -o /tmp/safe
/tmp/safe

CMake intro: a CMakeLists.txt identifies the project, sources and C++ standard; CMake generates a backend build. Learn cmake -S . -B build && cmake --build build; add CTest and a separate test target when moving from small single files to projects.

Interview: What does a sanitizer do? Instruments compiled programs to diagnose selected runtime defects. It does not prove absence of all bugs.

PART II — PYTHON & MATHEMATICS FOR AI

Lesson 15 — Python bridge for a C++ learner

Unlike C++, Python often runs by an interpreter and provides dynamic typing. A Python list is a high-level object, not a direct equivalent of a std::vector<int>. We use Python here because scikit-learn and standard PyTorch workflows are Python-centric.

scores = [80, 90, 100]
print(sum(scores) / len(scores))

def mean(values):
    if not values:
        raise ValueError("empty values")
    return sum(values) / len(values)

assert mean([2, 4, 6]) == 4

Study: numbers, strings, lists, tuples, dictionaries, sets, comprehensions, if, for, functions, modules, exceptions, context managers, classes, file I/O, virtual environments and pytest.

C++ comparison: vector<int> is constrained to int values and compiled; Python list can contain mixed objects. A dict resembles a hash map at a high level.

Debug: IndentationError means block spacing is inconsistent; TypeError means the operation is incompatible with supplied object types.

Checkpoint: Write a function accepting a list of grades and returning average, minimum, maximum and grade category, handling an empty list.

Lesson 16 — NumPy arrays, axes, shapes, and vectorization

ML often uses a matrix: rows represent examples; columns represent features. NumPy arrays are homogeneous numeric containers enabling fast bulk operations. shape=(100,4) means 100 examples, each with four features.

import numpy as np
X = np.array([[1., 2.], [3., 4.], [5., 6.]])
print(X.shape)         # (3, 2)
print(X.mean(axis=0))  # mean per column: [3.,4.]
print(X.mean(axis=1))  # mean per row: [1.5,3.5,5.5]

Broadcasting: combining arrays with compatible shapes without manually writing nested loops. Rules compare dimensions from the right; they must match or one must equal 1.

Debug: operands could not be broadcast together means incompatible shapes. Print a.shape, b.shape before attempting fixes.

Checkpoint: Make a (4,3) numeric dataset; center each feature by subtracting the training-only column means; verify resulting means are near zero.

Lesson 17 — Linear algebra without fear

A scalar is one number, a vector is an ordered collection, a matrix is a 2D grid, a tensor generalizes to more axes. A dot product measures weighted combination:

[a\cdot b = a_1b_1 + a_2b_2 + \cdots+a_nb_n]

A neuron computes approximately weighted_sum = x @ w + b. Matrix multiplication composes transformations; its shape rule is (m,n) @ (n,p) → (m,p).

import numpy as np
features = np.array([[2., 3.], [4., 5.]])   # (2 samples, 2 features)
weights = np.array([[0.5], [2.0]])          # (2 features, 1 output)
print(features @ weights)                  # (2, 1) output

Norm is a measure of vector magnitude. Transpose swaps axes. Eigenvectors capture important transform directions and appear in PCA later; start with geometric intuition, then formulas.

Debug: Wrong matrix dimensions produce errors; ensure the inner dimensions match. * in NumPy means elementwise multiplication, @ is matrix multiplication.

Interview: Why are tensor shapes important? They encode the structure of data and determine which operations are legal.

Lesson 18 — Statistics, probability and evaluation intuition

Mean is arithmetic average; median is middle ordered value; variance measures spread; standard deviation is the square root of variance. Outliers can distort the mean more than the median.

Probability represents uncertainty. Conditional probability P(A|B) means probability of A given B. Bayes' rule connects evidence and prior beliefs:

[P(A|B)=\frac{P(B|A)P(A)}{P(B)}]

ML evaluation has sampling uncertainty: one lucky split can make a weak model look excellent. Use stratification when appropriate, repeated experiments, cross-validation and confidence intervals where meaningful.

Practice: Analyze salaries [10,12,13,14,100] and explain why mean and median differ. Compute accuracy of a model predicting 'normal' for every case when 99 of 100 cases are normal.

Debug: Data distribution shift means the training population and real-world prediction population differ. Training success cannot guarantee deployed performance.

Interview: Why is 99% accuracy sometimes bad? With 99% majority-class prevalence, a constant-majority predictor can score 99% while detecting zero minority cases.

Lesson 19 — Calculus and gradient descent from scratch

A derivative tells how output changes when an input changes. A gradient collects derivatives for multiple parameters. The loss is a numerical penalty for model mistakes.

For linear regression prediction = w*x + b, mean squared error is

[L(w,b)=\frac{1}{n}\sum_{i=1}^{n}(wx_i+b-y_i)^2.]

Gradient descent adjusts parameters in the opposite direction to the slope:

[w \leftarrow w-\eta\frac{\partial L}{\partial w},\qquad b\leftarrow b-\eta\frac{\partial L}{\partial b}]

where η is learning rate. Too high makes updates overshoot; too low makes learning slow. A bad scale or noisy data complicates convergence.

Run: cpp/13_gradient_descent.cpp. It learns w≈2 and b≈1 on toy points. Change learning rate from 0.05 to 1.0 and observe instability—then fix it.

Debug: nan in loss can result from exploding numerical values, inappropriate learning rate, invalid math or bad inputs. Log inputs and parameter statistics before guessing.

Interview: What is a gradient? A vector of partial derivatives of a scalar-valued objective with respect to each parameter.

PART III — MACHINE LEARNING USING SCIKIT-LEARN

Lesson 20 — ML in plain language: supervised vs unsupervised

A model is a function fitted from examples. In supervised learning, each example has a target: input features X and answer y. Classification predicts a category; regression predicts a continuous value. In unsupervised learning, no direct target is given; we identify structure, clusters or anomalies.

DATA  (X, y)  → train/validation/test boundaries
                    ↓
TRAINING DATA → preprocess.fit → model.fit
                    ↓
HELD-OUT DATA → preprocess.transform → model.predict → metrics

fit means learn from data, transform means apply learned transformation, predict means generate model outputs. A baseline is the simplest meaningful reference (majority-class classifier or average-value regressor). If your fancy model loses to the baseline, don't deploy it.

Checkpoint: Categorize spam detection, house-price estimation, customer grouping and suspicious-event discovery as classification/regression/clustering/anomaly detection.

Lesson 21 — Splitting data and the leakage trap

A test set is a final exam. If a teacher hands you the answer key before your practice, exam marks are no longer trustworthy. Data leakage happens when the model sees information it should not know before prediction time.

from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)

random_state helps reproduce the split. Stratification preserves approximate class proportions for classification. Time-series tasks must use chronological splits; random splits can leak future information. Grouped cases (multiple records for same patient/customer/device) need group-aware splitting.

Wrong: scaler.fit_transform(X) before splitting. Correct: split first; fit preprocessing on training data only, usually through Pipeline.

Debug: suspicious 100% accuracy? Check duplicate records, split-by-entity/time leakage, columns that directly encode target, preprocessing fit on whole dataset.

Interview: Train vs validation vs test? Train learns parameters, validation chooses settings/model, test gives final minimally biased evaluation.

Lesson 22 — Regression: linear, regularized, errors

Linear regression approximates y = w1*x1 + ... + b. Ridge regression penalizes large weights with L2 regularization, often helping with unstable/highly correlated features. Lasso uses L1 penalty and can zero some coefficients.

  • MAE: mean absolute error; same units as target.
  • MSE: mean squared error; emphasizes larger errors.
  • RMSE: square root of MSE; original units.
  • R²: compares fit against predicting the target mean; can be negative on unseen data.

Run: ml/02_regression.py. It compares a mean-prediction baseline to Ridge on synthetic data. Describe why the better model is better using multiple metrics, not one number.

Debug: If training MAE is small but test MAE is huge, inspect leakage, overfitting, changed feature schema and label distribution.

Interview: Why would you choose MAE over RMSE? MAE is less sensitive to a few large errors; metric choice depends on business costs.

Lesson 23 — Classification: logistic regression and metrics

Despite its name, logistic regression is a classification algorithm. It forms a linear score and maps it to a probability (binary case) using a sigmoid:

[\sigma(z)=\frac{1}{1+e^{-z}}]

Confusion matrix: TP = correctly predicted positive; FP = false alarm; FN = missed positive; TN = correctly predicted negative.

[\text{precision}=TP/(TP+FP), \quad \text{recall}=TP/(TP+FN)]

F1 is the harmonic mean of precision and recall. For rare suspicious logins, high recall may detect more true threats but produce more false alerts; tune the threshold in collaboration with the domain owner.

Run: ml/01_iris_classification.py. Interpret the confusion matrix; manually compute precision and recall for one class.

Debug: Accuracy overstates success under imbalance. Inspect per-class scores, PR curve, confusion matrix and decision thresholds.

Interview: Precision vs recall? Precision asks how many flagged were correct; recall asks how many actual positives were found.

Lesson 24 — Trees, ensembles and overfitting

A decision tree repeatedly asks split questions such as feature < threshold?. Deep trees can memorize training data; controlling depth or minimum leaf size helps regularize. A random forest trains many varied trees and aggregates predictions. Gradient boosting adds weak learners sequentially to correct errors.

from sklearn.ensemble import RandomForestClassifier
model = RandomForestClassifier(n_estimators=100, random_state=0)
model.fit(X_train, y_train)

Trees generally do not require standardizing numeric features, but missing-value and categorical handling depend on the particular estimator and its version. Always check estimator documentation.

Practice: Train logistic regression and random forest on the same split. Compare macro F1, latency and feature interpretability.

Debug: Huge difference between train and test scores is often high variance/overfitting; reduce complexity, get more representative data or tune using cross-validation.

Interview: Bagging vs boosting? Bagging aggregates models built from varied samples; boosting builds learners sequentially to improve a chosen objective.

Lesson 25 — Preprocessing, pipelines and categorical values

Real columns have missing data, strings, numeric values with different scales and outliers. Fit all learned preprocessing inside a pipeline. ColumnTransformer can apply separate steps to different feature types.

from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

preprocess = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), ["age", "salary"]),
    ("cat", OneHotEncoder(handle_unknown="ignore"), ["city"])
])
model = Pipeline([("preprocess", preprocess),
                  ("classifier", LogisticRegression(max_iter=500))])
# Requires pandas DataFrame with these exact columns.

Debug: Found unknown categories happens when prediction has unseen category values and the encoder was not configured to handle them. Never refit preprocessing on live prediction requests.

Interview: Why pipelines? A single object encodes ordered transformations, reduces leakage risk and supports cross-validation/deployment consistency.

Lesson 26 — Cross-validation and hyperparameter tuning

A hyperparameter is chosen outside the model fitting process (e.g., Ridge alpha, classifier C, tree max depth). A parameter (like model weights) is learned from training data.

K-fold cross-validation partitions training data into K folds; each fold serves as validation once. It estimates generalization variability more reliably than one arbitrary split, but grouped and chronological scenarios need suitable CV strategies.

Run: ml/03_cross_validation.py. It tunes logistic regression C on training folds and reports untouched holdout performance.

Debug: Never search hyperparameters on the test set. n_jobs=-1 may overwhelm an 8 GB laptop; use n_jobs=1 or a small number.

Interview: Does cross-validation eliminate leakage? No. Leakage can still enter through feature engineering, repeated test inspection or inappropriate split strategy.

Lesson 27 — Clustering, anomaly detection and fair model reporting

K-means assigns points to K clusters based on distances; it assumes roughly compact/spherical groupings and requires choosing K. Silhouette score measures separation/cohesion, but it doesn't prove clusters correspond to real-world meaningful groups.

Isolation Forest isolates unusual observations using random splits. Anomaly score is not a calibrated probability of attack or fraud; real production needs ground-truth evaluation, alert-volume constraints and analyst feedback.

Run: ml/04_clustering.py and ml/05_anomaly_detection.py. The anomaly example is deliberately synthetic; explain why its very high detection rate is not evidence it will work on real SOC events.

Debug: Feeding train/test from a different column order can silently break a model. Validate feature names, types, missingness, ranges and drift.

Interview: Supervised fraud detection vs unsupervised anomaly detection? The former learns from labeled fraud examples, while the latter flags statistical unusualness without necessarily knowing fraud labels.

PART IV — DEEP LEARNING WITH PYTORCH

Lesson 28 — PyTorch mental model: tensors, devices and dtypes

A tensor is a multi-dimensional array. A grayscale image may be shaped (height,width), but a batch for a CNN is commonly (batch,channels,height,width). An input features batch might be (32,10): 32 rows, 10 features each.

import torch
x = torch.tensor([[1., 2.], [3., 4.]])
print(x.shape, x.dtype, x.device)

Dtype matters: input features often torch.float32; class indices for CrossEntropyLoss must generally be torch.long. A CPU-only machine reports cpu, and that's fine.

Run: pytorch/01_tensors.py. Predict the output shape of A + b and A @ A.

Debug: mat1 and mat2 shapes cannot be multiplied means layer or matrix dimensions disagree; trace shapes from the earliest input.

Interview: NumPy arrays vs PyTorch tensors? Both do numerical arrays; PyTorch tensors integrate with automatic differentiation and hardware acceleration backends.

Lesson 29 — Autograd and computation graphs

PyTorch tracks differentiable operations on tensors marked requires_grad=True. A computation graph records how an output depends on inputs; backward() applies the chain rule to compute gradients.

x = torch.tensor(3.0, requires_grad=True)
y = x * x
# dy/dx = 2*x, so at x=3 gradient is 6
y.backward()
print(x.grad)  # tensor(6.)

Run: pytorch/02_autograd.py. Change y=x**3 + 2*x and calculate expected gradient analytically before running (3x²+2).

Debug: If loss.backward() says a tensor does not require grad, check .detach(), torch.no_grad(), non-differentiable operations or model parameters accidentally frozen. Gradient accumulation is default for leaf parameters.

Interview: What does autograd do? Applies the chain rule through tracked tensor operations to calculate derivatives for training.

Lesson 30 — Neurons, layers, activation functions

A basic artificial neuron computes z = w·x + b, then applies an activation a=f(z). A network stacks transformations. Nonlinear activation is critical: stacking purely linear layers still reduces to one linear transformation.

import torch.nn as nn
model = nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 3))

Input (batch,4) becomes (batch,8) then (batch,3). The final three raw outputs are logits for three classes. Don't blindly add softmax before nn.CrossEntropyLoss: that loss already handles log-softmax internally.

Practice: Draw a 4→8→3 network; count trainable parameters: first layer 48+8=40; second 83+3=27; total 67.

Debug: Expected target size/shape mismatch often means wrong class-target shape, incorrect logits shape or passing one-hot labels when class-index labels are expected.

Interview: Why do networks need nonlinearities? Without them, chained linear layers cannot represent nonlinear decision boundaries.

Lesson 31 — A complete training loop

Training means: forward pass → calculate loss → clear prior grads → backpropagate → update parameters. Repeat across batches and epochs.

model.train()
for x_batch, y_batch in loader:
    optimizer.zero_grad()
    predictions = model(x_batch)
    loss = criterion(predictions, y_batch)
    loss.backward()
    optimizer.step()

Epoch = one sweep through training examples. Batch = a subset used for one update. Learning rate controls update size. Optimizer implements parameter update strategy (SGD, Adam etc.).

Run: pytorch/03_linear_regression.py. Compare the learned parameters to cpp/13_gradient_descent.cpp; same mathematical idea, different implementation.

Debug: Loss does not decrease? Check learning rate, dtype, label alignment, gradient flow, model initialization and whether optimizer actually receives model parameters.

Interview: Why zero_grad()? PyTorch accumulates gradients by default, so clearing prevents unintended accumulation across standard training steps.

Lesson 32 — Classification network with a real train/test boundary

Use make_moons to create an illustrative 2D curved classification task. Scikit-learn splits and standardizes data using training-only statistics; PyTorch learns a nonlinear decision boundary. This combines the two frameworks correctly.

Run: pytorch/04_mlp_classification.py. It uses nn.Linear → ReLU → Linear, CrossEntropyLoss and Adam on small data. Note model.train() during training and model.eval() + torch.inference_mode() during evaluation.

Experiment: Reduce hidden units 16→1, compare accuracy. Try learning rates .001, .03, .5 and record stability. Never tune repeatedly on the held-out test set; add a validation split for fair tuning.

Debug: RuntimeError: expected scalar type Long but found Float often indicates class targets wrongly encoded as float. Convert class index tensor with .long() (only if the task requires class indices).

Interview: Why is model.eval() needed? Some layers like dropout and batch normalization behave differently during evaluation than training.

Lesson 33 — Dataset and DataLoader

Dataset defines __len__ and __getitem__; DataLoader groups samples into batches, optionally shuffles, and can use worker processes. On modest hardware, start with num_workers=0.

Run: pytorch/05_dataloader.py. It creates 96 samples with 3 features each, yields a first mini-batch (16,3) and labels (16,).

Practice: Change batch size to 7. Predict number of batches: ceil(96/7)=14; the last batch contains 5 examples unless drop_last=True.

Debug: DataLoader hangs? Start by setting num_workers=0, make sure dataset indexing returns valid types and isolate one sample with dataset[0].

Interview: What is the difference between a batch and an epoch? One batch is a subset for one step; an epoch processes the training set once.

Lesson 34 — Generalization, regularization and diagnostics

Overfitting: excellent performance on training data, poor on new data. Underfitting: poor performance on both. Common controls: better data, smaller models, weight decay, dropout, augmentation, early stopping and robust validation.

Run: pytorch/07_validation.py. Compare train_mse and val_mse every 25 epochs. If validation begins rising while train continues falling, suspect overfitting. For time series or clustered data, choose an appropriate validation split first.

Debug: Loss becomes NaN? Log batch min/max, check finite data and weights, lower learning rate, check divisions/logarithms and consider gradient clipping for unstable training. torch.isnan(loss) can be a useful diagnostic.

Interview: Dropout vs weight decay? Dropout randomly zeroes activations during training; weight decay discourages large parameter values through optimizer regularization.

Lesson 35 — Convolutional neural networks (CNN) basics

A CNN applies small learned filters across an image to find local patterns like edges. Conv2d uses (batch,channels,height,width) in PyTorch. After a valid 3×3 convolution with stride 1 and no padding, a 16×16 image becomes 14×14.

Input: (N,1,16,16)
  → Conv2d(1,4,kernel=3)
  → (N,4,14,14)
  → ReLU → Flatten (N,784)
  → Linear(784,2) → two class logits

Run: pytorch/08_tiny_cnn.py. Entirely synthetic 16×16 horizontal-vs-vertical bars—no downloads or GPU. High accuracy here is only on this deliberately easy artificial dataset.

Practice: Replace one filter size with 5 and calculate flattened size. Add explicit shape prints to catch mismatches.

Debug: mat1 and mat2 shapes cannot be multiplied commonly follows a changed convolution kernel or pooling layer without updating the first dense layer's in_features.

Interview: Why CNNs? Weight sharing and local receptive fields exploit spatial structure efficiently compared with naive dense networks.

Lesson 36 — Saving, loading and inference safety

Save model parameters using state_dict, and recreate the same architecture before loading. Keep preprocessing artifacts, feature schema and class-name mapping alongside the weights. Version them and document the training environment.

Run: pytorch/06_save_load.py. It saves model weights to a temporary local file and loads them with weights_only=True.

Important security principle: Never load untrusted serialized model artifacts; Python pickle-based formats can execute code in unsafe loading contexts. PyTorch's weights_only=True reduces risk, but trust and validation remain important.

Debug: Missing key(s) in state_dict or Unexpected key(s) means saved weights and constructed architecture/key names do not match; inspect the training configuration and saved keys.

Interview: Why call inference mode? It avoids building autograd state for inference, reducing overhead when gradients are unnecessary.

PART V — REAL JOB-READY ENGINEERING PRACTICE

Lesson 37 — Testing and reproducibility

Professional developers don't submit only a notebook that runs once. They produce an environment, deterministic tests when practical, an error-handling strategy and clear usage instructions.

Your checklist: set random seeds; record library versions and input schema; split before learned preprocessing; compare baselines; report test metrics honestly; include at least 3 tests (happy path, empty/bad input, shape change); document limitations and the reproducibility boundary.

Test with:

python -m pytest -q
# Run specific script:
python ml/01_iris_classification.py

Reproducibility has limits across different hardware and library versions; fixed seed helps but does not universally guarantee bit-exact results.

Debug: A model that fails only in deployment might be seeing different schema, dependencies, numerical libraries, file permissions or serialization version.

Lesson 38 — API and deployment architecture

A typical local inference service looks like:

Client JSON request
      ↓
Input validation (types, schema, size limits)
      ↓
Versioned preprocessing → model inference
      ↓
Output validation + response
      ↓
Metrics/logs (no secrets or raw sensitive data)

Learn REST basics, request/response status codes, FastAPI (optional package for the capstone), Docker basics, versioning and health checks. Never allow arbitrary file paths or untrusted model uploads. Use access control for sensitive endpoints; sanitize logs.

Lab design: Turn your Iris model into /predict that accepts numeric features, returns class + model version, rejects missing fields with a 4xx response and has a /health endpoint. Write endpoint tests before deploying anywhere. Run locally; no external publishing is assumed.

Debug: HTTP 422 indicates input schema validation failure in many FastAPI apps; HTTP 500 means an unhandled server error. Separate bad-input bugs from internal errors.

Interview: What is train-serving skew? Difference between data transformations/conditions used for training and those encountered during serving.

Lesson 39 — Three resume-worthy capstones

Capstone A: C++ Log Analyzer (engineering and DSA)

Implement a command-line log analyzer supporting timestamp parsing, severity counts, filtering, top-K event types and deterministic summary. Handle invalid lines, large-ish files without loading everything, empty input and Unicode/encoding caveats. Use classes only when they improve design. Add unit tests and sanitizer runs. Explain O(n) scans, memory overhead, and trade-offs.

Acceptance: sample logs + documented schema; 10 tests; robust error paths; README; an example performance measurement; no unsafe pointer ownership.

Capstone B: scikit-learn Risk Classification Pipeline

Use a trustworthy public labeled dataset (or synthetic for first iteration). Define a non-sensitive risk classification task, baseline model, feature preprocessing in Pipeline, stratified or grouped split as appropriate, CV inside training only, F1/recall/precision/confusion matrix, threshold selection and error analysis. Avoid claiming synthetic metrics represent real world.

Acceptance: reproducible script, train/eval separation, proper leakage prevention, final test set used once for the selected model, model-card limitations and an inference example.

Capstone C: PyTorch Neural Network Classifier

Train a small MLP or CNN on an appropriately sized public dataset (start with the supplied synthetic one). Implement Dataset/DataLoader, training/validation curves, seeds, optimizer choice, checkpoint weights and batch inference. Add shape tests and a controlled ablation: learning rate, width or weight decay.

Acceptance: training loop written by you, shape tracing, test metrics, comparison with baseline, versioned weights, secure loading guidance, CPU instructions and failure modes.

Lesson 40 — How to prepare for real interviews

A strong answer usually follows this pattern: definition → why → tiny example → edge case → debugging → trade-off.

Example prompt: "What is overfitting?" Say: "Model training data pe achha perform karta hai, unseen data pe weak. Main training-vs-validation score compare karunga, leakage check karunga, then regularization or more representative data try karunga. Test set ko tuning ke liye use nahi karunga."

Interviews may assess live coding, C++ ownership, DSA, ML statistics, leakage, class imbalance, tensor shape, gradients, experiment design, system design and problem-solving under uncertainty. Use INTERVIEW_QA.md for rehearsals and ASSESSMENTS.md as gates.
