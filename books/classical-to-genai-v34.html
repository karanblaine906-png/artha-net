DevAI Academy V34: Classical Artificial Intelligence → Python → GenAI Engineering

What was actually implemented

This is an additive source-code upgrade to the previously supplied DevAI Academy V33. It does not replace old user courses or their progress. It adds:

  • One selectable integrated course: Classical AI to GenAI Engineering with 45 classical lecture-title checkpoints and 160 existing modern AI checkpoints = 205 lessons across 38 chapters (Complete mode).
  • Individual, locally authored explanation pages for all 45 classical topics. Titles are transcribed from user-supplied screenshots, not independently checked against the complete 48-video NPTEL playlist or spoken video content. The 160 existing v33 foundation explanations remain available.
  • Seven additional offline Python labs, expanding to 15 executed dependency-free/small standard-library demonstrations overall; an optional toy-training transformer and specialized PyTorch/TensorFlow/LangGraph/MCP scripts remain in ai_labs/optional.
  • A course-specific YouTube video inventory importer: saves verified-shape public YouTube links and titles; proposes provisional lesson associations by title similarity; exports CSV. Does not watch, download video/audio, extract transcripts, create embeddings, or claim copyright ownership.
  • A lesson-specific matching lab recommendation in the classroom. Commands display for you to run in a local terminal; the server does not execute learner-selected lab commands.
  • Existing private login, progress SQLite, local AI teacher, supervised quizzes, PDF reference search and legacy classroom are preserved.

These are structured learning checkpoints and tested teaching demos, not 205 long professional lessons or 205 independently deployed real-world projects. Moving to expert competency requires repeated labs, independent source checking, realistic data, supervised review and production-like capstone validation.

How to run on Debian 12 / 8 GB RAM

In your terminal (project root, after unzipping):

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python start_local.py

Open http://127.0.0.1:8000 on the same computer. For the Owner login use the access token printed on first startup. Do not share .local-secrets or the SQLite database.

Create a new course by choosing Classical AI to GenAI Engineering (205) from the New Course page. Use Complete (or Expert/Job Ready for the full structure), select mentor DevAI or ARTHA Mentor, click Teach this lesson. Leave the external AI checkbox off for the authored offline notes; otherwise provider configuration and per-request consent are needed. Select each lesson to see its corresponding executable lab recommendation, where one exists.

Offline terminal labs (run from the extracted project root):

YouTube playlist inventory: two modes

Offline / no permission or network required: Paste lines such as Video title | https://youtu.be/VIDEO_ID or the exported scraper's CSV into the classroom's Public YouTube playlist → Course references section. This checks and deduplicates YouTube video ID shapes and saves metadata; titles supplied by users are not independently confirmed.

Live playlist / channel extraction: On your own computer, explicitly approve an Internet request, install optional yt-dlp only if approved, and run the Academy with network opt-in:

python -m pip install yt-dlp      # optional, needs approved package access
export DEVAI_NETWORK_ENABLED=1    # admin gate, only when approved
python start_local.py

Paste a public HTTPS URL from youtube.com, e.g. a playlist or @channel/videos. Click Import, review the one-request destination/consent prompt, and approve. The service then invokes yt-dlp in flat metadata-only mode to collect available video titles and direct links. Import is bounded to max 500 links (browser currently requests max 250). No unapproved background fetching. Stop the service and unset DEVAI_NETWORK_ENABLED to return to default-deny networking. Note that enabling networking may also enable other separately consent-gated integrations in the project; review the existing system's backend/network_policy.py and related endpoints before enabling on sensitive machines.

Coverage limitation: Private/deleted/unavailable videos, YouTube blocking and rate limits can produce partial results. The importer has no transcript/content verification, and automatically suggested lesson mappings must be manually reviewed. Exact titles imply a string match, not independently proven conceptual equivalence.

Example bridge: one connected question through eight levels

Capstone brief: Build a local, evidence-aware mini troubleshooting tutor for synthetic Linux logs. Begin with basic Python and finish with a locally tested API and restricted tools. Do not ingest real sensitive incident logs.

Stage Concept to master Build and acceptance test
0 Python, math, list/dict, functions Parse 20 synthetic log lines into records; unit-test malformed input
1 Classical AI graph search and rules Represent diagnostic hypotheses as a graph; compare BFS/DFS/A* and forward-chaining rules
2 Machine learning classification Fit toy logistic regression; show leakage-safe train/test split and precision/recall on a separate fixture
3 Deep learning Manually train a tiny neural network; explain each gradient and test a mismatched feature shape
4 Transformer/LLM concepts Implement masked attention, explain Q/K/V and train a toy decoder only with approved installed PyTorch
5 Evidence-aware RAG Index synthetic troubleshooting notes, retrieve only authorized passages, cite source IDs, and abstain on missing evidence
6 Agentic AI / tools Propose a read-only diagnostic tool; validate typed arguments; require explicit approval for any external operation; log actual result
7 Deploy/operate Run localhost API, test invalid inputs and source isolation, record CPU/RAM cost and response latency, draft rollback SOP

Lab practice protocol

For every lab, write five things: expected output, actual output, why they differ, edge-case test, and production/security limitation. If a step fails, the right answer is to debug and document it, not mark it mastered. Persist the markdown evidence next to your own project copy; the web app currently stores self-reported progress rather than verified submitted code/test artifacts.

Verification ladder

  1. 15 stdlib AI lab scripts executed on the build machine (01–06, 08–16).
  2. FastAPI backend, consent controls, course generation, lesson lookup, saved playlist inventory and CSV export tested by automated HTTP tests.
  3. yt-dlp live scraping not tested against YouTube in this build; mocked integration path tested, opt-in gate tested.
  4. Browser UI: JS syntax checked, but Chromium navigation to the local server was blocked by the tool environment. Test locally using your browser after extraction.
  5. Optional PyTorch / TensorFlow / LangGraph / MCP live SDK compatibility and deployment not asserted by V34 tests. Real foundation-model training and GPU systems are beyond the offline laptop exercises.

Suggested six-stage learning sequence

  • Stage A (weeks 1–4): Python basics + graph search + complexity; implement BFS, DFS, A*, IDDFS; test unreachable targets.
  • Stage B (weeks 5–8): Logic, planning, CSP and algorithms for games; explain minimax, alpha-beta, resolution vs chaining.
  • Stage C (weeks 9–12): ML and math; implement regression, logistic classification, clustering and reproducible evaluation.
  • Stage D (weeks 13–16): Neural-network backprop, embeddings, tokenization, masked attention and toy transformer training.
  • Stage E (weeks 17–20): RAG indexing/citations, agents, typed tools, LangGraph/MCP optional integration and injection/permission tests.
  • Stage F (weeks 21–24): Model serving, metrics, threat modeling, container/API integration, capstone review and mock interviews.

This schedule is a suggested study plan, not proof of job readiness. On an 8 GB CPU-only device, start with the offline scripts and use free local examples; GPU model training may require resources or approved external infrastructure not included in the project.
