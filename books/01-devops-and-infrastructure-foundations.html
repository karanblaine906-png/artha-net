1.2 The Infrastructure Problem

Applications require infrastructure.

A simple application may need:

Application
    |
    +--> Compute
    +--> Operating System
    +--> Network
    +--> Storage
    +--> Database
    +--> Security
    +--> Monitoring

At small scale, an administrator can configure these components manually.

At production scale, manual administration becomes difficult.

1.4 Configuration Drift

Suppose three servers should be identical:

web01
web02
web03

Initially:

Apache 2.x
Same configuration
Same application

After several months:

web01 -> package manually upgraded
web02 -> configuration manually edited
web03 -> firewall rule manually changed

The servers are no longer identical.

This is:

Configuration Drift

Automation and configuration management reduce this problem.

1.5 The DevOps Problem

Traditional organizations often separate:

Development

and:

Operations

Developers may say:

"It works on my machine."

Operations may say:

"It does not work in production."

The deeper problem is often:

Different environments
Manual handoffs
Slow feedback
Unclear ownership
Poor automation

1.12 VM vs Container

Feature Virtual Machine Container
Guest OS Usually yes Shares host kernel
Startup Usually slower Usually faster
Image size Larger Often smaller
Isolation VM boundary OS/container boundary
Portability Good Excellent for application packaging

Containers and VMs are complementary technologies.

1.17 Desired State

Suppose you declare:

I want 3 application replicas.

Current state:

2 replicas

Kubernetes detects the difference.

Desired = 3
Current = 2
Difference = 1

Controller action:

Create another replica

1.18 Reconciliation

Kubernetes continuously compares:

Desired State

with:

Current State

Workflow:

Desired State
      |
      v
Controller
      |
      v
Observe Current State
      |
      v
Difference?
  /       \
YES       NO
 |         |
 v         v
Act       Wait

This process is called:

Reconciliation

1.19 Self-Healing

Suppose:

Desired replicas = 3

One Pod fails:

Running = 2

Kubernetes works to restore:

Running = 3

This is one example of self-healing behavior.

1.55 Common Mistakes

  1. Thinking DevOps means only Jenkins.
  2. Thinking Kubernetes replaces Linux.
  3. Thinking Terraform replaces Ansible in every case.
  4. Treating production like a manual lab.
  5. Deploying without monitoring.
  6. Monitoring without alerting.
  7. Logging without retention planning.
  8. Giving CI/CD administrator permissions.
  9. Storing secrets in Git.
  10. Changing production manually without recording the change.
  11. Restarting services before understanding the incident.
  12. Learning tools without understanding networking and Linux.

1.56 Interview Questions

Q1. What is DevOps?

DevOps is a combination of culture, processes and engineering practices that improves collaboration and automates software delivery and operations.

Q2. What is Infrastructure as Code?

Infrastructure as Code describes and manages infrastructure using version-controlled configuration/code.

Q3. Terraform vs Ansible?

Terraform is commonly used to provision and manage infrastructure resources.

Ansible is commonly used for configuration management and operational automation.

They can work together.

Q4. Why Kubernetes?

Kubernetes automates scheduling, scaling, service discovery, self-healing and lifecycle management for containerized workloads.

Q5. Prometheus vs ELK?

Prometheus primarily focuses on metrics.

ELK primarily focuses on log ingestion, search and visualization.
