Chapter 1 — From Source Code to Running Program

Outcomes

After this chapter you can describe the C++ toolchain, build a C++ program on Debian 12, distinguish compile errors from link errors and runtime failures, inspect the compilation pipeline, use basic GDB, and answer entry-level interview questions.

1.1 What is C++?

C++ is a compiled, statically typed, general-purpose programming language supporting procedural, object-oriented and generic styles. It is used in systems software, games, browsers, low-latency services, databases and embedded software. C++ gives explicit control over object lifetime and resource management, but that flexibility makes undefined behavior and lifetime mistakes important concerns.

A source file (.cpp) contains text that a compiler translates. A header (.h, .hpp) typically exposes declarations. An object file (.o) contains machine code and metadata that is not yet necessarily a complete executable. A linker combines object files and libraries, resolving external symbols. The operating-system loader maps executable segments and needed shared libraries into a process and transfers control to startup code, which calls main.

1.2 Prepare Debian 12

Run these commands in your terminal, not inside C++ source code:

sudo apt update
sudo apt install -y build-essential gdb cmake ninja-build binutils file
c++ --version
gdb --version

build-essential supplies the compiler toolchain and build essentials. gdb is the debugger; binutils supplies tools such as nm, objdump and readelf. Package versions differ by system; the baseline examples require only C++17.

1.3 First program

Create main.cpp:

#include <iostream>

int main() {
    std::cout << "Hello, C++ Engineer!\n";
    return 0;
}

Line by line

  1. #include <iostream> requests declarations for standard stream I/O; preprocessing handles the include directive.
  2. int main() defines the hosted program's entry-point function, returning an integer status.
  3. { begins the function body.
  4. std::cout is the standard output stream; << inserts text into it. \n is a newline character.
  5. return 0; indicates successful termination. Reaching the end of main also returns zero.
  6. } ends the function.

Compile and run:

g++ -std=c++17 -Wall -Wextra -Wpedantic -g -O0 main.cpp -o hello
./hello
printf 'Exit status: %s\n' "$?"

Expected:

Hello, C++ Engineer!
Exit status: 0

Flags: -std=c++17 selects a standard; -Wall -Wextra -Wpedantic enable useful diagnostics; -g includes debug information; -O0 disables optimization for easier introductory debugging; -o hello sets the output filename.

1.4 The compilation pipeline

main.cpp
   |
   v
Preprocessor (includes, macros, conditional compilation)
   |
   v
Compiler (C++ semantics, optimization, assembly generation)
   |
   v
Assembler (machine code and relocations in main.o)
   |
   v
Linker (symbols, libraries, executable)
   |
   v
Linux ELF loader + runtime initialization
   |
   v
main() -> output -> process exit

Observe intermediate outputs:

g++ -std=c++17 -E main.cpp -o main.ii
g++ -std=c++17 -S main.cpp -o main.s
g++ -std=c++17 -c main.cpp -o main.o
g++ main.o -o hello
file hello
readelf -h hello | head -n 20
nm -C main.o | grep main

The preprocessed file is large because the standard header expands into many declarations. Assembly is architecture/compiler dependent. readelf describes the ELF header; nm -C displays demangled symbols. The linker may produce a position-independent executable by default depending on distribution configuration.

1.5 Compile vs link vs runtime error

Compile error: malformed C++:

int main() {
    int x = ;
}

The compiler rejects invalid syntax before producing a usable object file.

Link error: a function is declared but never defined:

int calculate();
int main() { return calculate(); }

The compiler can compile this translation unit, but the linker typically reports an undefined reference to calculate().

Runtime error: code builds but fails during execution. Examples include an uncaught exception or an invalid memory access. Importantly, undefined behavior does not guarantee a crash; it can produce unpredictable behavior.

1.6 Debug with GDB

Create debug.cpp:

#include <iostream>
int square(int x) {
    int result = x * x;
    return result;
}
int main() {
    int number = 7;
    std::cout << square(number) << '\n';
}

Build and start GDB:

g++ -std=c++17 -g -O0 -Wall -Wextra debug.cpp -o debug
gdb ./debug

At the (gdb) prompt:

break square
run
info args
next
print result
backtrace
continue
quit

A breakpoint pauses execution in square. info args shows parameters; next executes the next source line without entering called functions; print result evaluates a variable after assignment; backtrace displays stack frames.

1.7 Build and inspect a two-file program

math_ops.hpp:

#pragma once
int add(int a, int b);

math_ops.cpp:

#include "math_ops.hpp"
int add(int a, int b) { return a + b; }

app.cpp:

#include <iostream>
#include "math_ops.hpp"
int main() {
    std::cout << add(2, 3) << '\n';
}

Build:

g++ -std=c++17 -Wall -Wextra -Wpedantic -c math_ops.cpp -o math_ops.o
g++ -std=c++17 -Wall -Wextra -Wpedantic -c app.cpp -o app.o
g++ math_ops.o app.o -o app
./app

Expected output: 5. Remove math_ops.o from the final link command and observe the undefined-reference error. This is a controlled demonstration of symbol resolution.

1.10 Interview questions and model answers

Q1. Is C++ compiled or interpreted?
Typically compiled to native machine code. Other execution models exist, but GCC/Clang/MSVC native compilation is the standard production workflow.

Q2. What is the difference between a compiler and a linker?
A compiler processes a translation unit and produces object code; a linker combines objects/libraries and resolves symbols to create a loadable output.

Q3. What is a translation unit?
The source file after preprocessing, including text introduced by headers.

Q4. Why use header files?
To expose reusable declarations and interfaces across translation units. Definitions placed in headers need appropriate rules such as inline or templates to avoid violating the One Definition Rule.

Q5. What does return 0 in main mean?
Successful program termination in a hosted C++ environment.

Q6. What is undefined behavior?
Program behavior for which the C++ standard imposes no requirements; the result is not necessarily a crash or diagnostic.

Q7. Why compile with -g?
To include debugging metadata so tools can associate machine instructions with source lines and symbols.

Q8. What does -O0 do?
Requests no optimization; this generally makes source-level debugging easier but is not a production performance choice.

Q9. What is ELF?
The Executable and Linkable Format used for object files, executables and shared objects on many Unix-like systems, including Linux.

Q10. What is the role of the operating system loader?
It maps the executable and required runtime components into a process, arranges execution prerequisites, and transfers control to program startup code.

Glossary

ABI: conventions governing binary compatibility, calling, and layout.
Compiler: translates C++ translation units into lower-level output.
ELF: Linux executable/object file format.
Linker: combines compiled objects and resolves symbols.
Loader: prepares executable images for process execution.
Object file: compiled code and metadata awaiting linking or further processing.
Translation unit: preprocessed source compiled as a unit.
Undefined behavior: behavior with no requirements imposed by the C++ standard.

Chapter 02 — Variables, Types, Expressions and Conversions

Learning objectives and prerequisite check

By the end, explain the language rules, write a small application without copying a tutorial, use compiler diagnostics, and diagnose at least one failure. Prerequisites: Chapter 1.

Conceptual model

C++ source describes operations on objects with types and lifetimes. The compiler checks syntax and many type constraints, but cannot prove that all runtime inputs are valid. The engineer is responsible for validating external inputs and preserving invariants.

Detailed explanations

Initialization vs assignment. int x{{}}; value-initializes to zero; int x; as an uninitialized automatic local has an indeterminate value and must not be read. const prevents modifying through that name, while constexpr requires a compile-time constant expression in its defining context. auto deduces types but does not imply dynamic typing.

Integer arithmetic. Signed overflow is undefined behavior; unsigned arithmetic wraps modulo 2^N. Mixing signed and unsigned values can change comparison meaning through usual arithmetic conversions. Prefer range checks before multiplication and use explicit types such as std::int64_t when exact widths are needed.

Floating point. Binary floating-point cannot represent many decimal fractions exactly. Compare with an application-specific tolerance, not a universal magic epsilon. NaN is unequal to itself; infinity can result from some floating operations.

Conversions. Braced initialization rejects many narrowing conversions. static_cast makes intended conversions explicit but does not make an out-of-range value safe. Avoid C-style casts in new code.

Worked example

The following is an instructional example. Read each statement and identify its input, output, state changes, and failure path.

#include <iostream>
#include <limits>
#include <string>
int main() {
    long long value{};
    std::cout << "Enter a nonnegative integer: ";
    if (!(std::cin >> value) || value < 0 || value > 1000000) {
        std::cerr << "Invalid input\n";
        return 1;
    }
    std::cout << "Square: " << value * value << "\n";
}

Expected behavior: Input 12 → Square: 144; input -1 → Invalid input.

Chapter 03 — Control Flow, Functions and Scope

Learning objectives and prerequisite check

By the end, explain the language rules, write a small application without copying a tutorial, use compiler diagnostics, and diagnose at least one failure. Prerequisites: Chapter 2.

Conceptual model

C++ source describes operations on objects with types and lifetimes. The compiler checks syntax and many type constraints, but cannot prove that all runtime inputs are valid. The engineer is responsible for validating external inputs and preserving invariants.

Detailed explanations

Branching. if handles arbitrary Boolean expressions; switch handles integral/enum selections. A switch branch can fall through if no break, return, or other control transfer occurs; use [[fallthrough]] when intentional.

Loops. for expresses a bounded iteration, while repeats while a condition holds, and do always executes at least once. Every loop needs a termination argument. Prefer range-for for element traversal.

Functions. Declarations communicate an interface; definitions provide an implementation. Overload resolution considers argument types and conversions. Passing a large immutable object by const T& avoids a copy; small scalar values are usually simplest by value. Recursion consumes call-stack space and must have a base case.

Scope and linkage. Local variables are visible within their block; namespace-scope names may have external or internal linkage. Use namespaces to avoid collisions and do not put using namespace std; in public headers.

Worked example

The following is an instructional example. Read each statement and identify its input, output, state changes, and failure path.

#include <iostream>
int add(int a, int b) { return a + b; }
int main() {
    int a{}, b{};
    if (!(std::cin >> a >> b)) { std::cerr << "Invalid integers\n"; return 1; }
    std::cout << add(a, b) << '\n';
}

Chapter 04 — Arrays, Strings, References and Pointers

Learning objectives and prerequisite check

By the end, explain the language rules, write a small application without copying a tutorial, use compiler diagnostics, and diagnose at least one failure. Prerequisites: Chapter 3.

Conceptual model

C++ source describes operations on objects with types and lifetimes. The compiler checks syntax and many type constraints, but cannot prove that all runtime inputs are valid. The engineer is responsible for validating external inputs and preserving invariants.

Detailed explanations

Arrays and vectors. Built-in arrays have fixed extents and can decay to pointers in many expressions. std::array<T,N> retains its size in the type. std::vector<T> owns a dynamically sized contiguous sequence; growth may invalidate pointers, references and iterators.

Strings. std::string owns characters and manages memory. std::string_view borrows characters and must not outlive the backing storage. std::getline reads a whole line; operator>> reads whitespace-delimited tokens.

References and pointers. A reference aliases an object; a pointer can be null and can be reseated. Dereferencing null, an invalid address, or an object past its lifetime is undefined behavior. Prefer references for required parameters, pointers for optional access, and owning containers/smart pointers for ownership.

Bounds. v.at(i) checks bounds and throws; v[i] requires the caller to ensure the index is valid. A half-open range [begin,end) simplifies traversal and avoids many off-by-one bugs.

Worked example

The following is an instructional example. Read each statement and identify its input, output, state changes, and failure path.

#include <iostream>

int main() {

    std::getline(std::cin, line);
    std::istringstream in(line);
    std::unordered_map<std::string, int> counts;
    while (in >> word) ++counts[word];
    for (const auto& entry : counts)
        std::cout << entry.first << ": " << entry.second << '\n';
}

Chapter 05 — Program Organization and Build Fundamentals

Learning objectives and prerequisite check

By the end, explain the language rules, write a small application without copying a tutorial, use compiler diagnostics, and diagnose at least one failure. Prerequisites: Chapter 4.

Conceptual model

C++ source describes operations on objects with types and lifetimes. The compiler checks syntax and many type constraints, but cannot prove that all runtime inputs are valid. The engineer is responsible for validating external inputs and preserving invariants.

Detailed explanations

Translation units. Each .cpp file is preprocessed and compiled independently. Headers provide declarations and templates; source files provide ordinary function definitions. The linker resolves references to external symbols.

One-definition rule. Non-inline functions with external linkage generally need one definition in the program. A non-inline function defined in a header and included in multiple .cpp files can cause duplicate symbol errors. Include guards or #pragma once prevent duplicate inclusion within a translation unit, not ODR violations across translation units.

CMake. Prefer target-oriented commands (add_library, target_include_directories, target_compile_features) rather than global flags. Keep build output outside source directories. Tests should exercise public interfaces, not private implementation details.

Worked example

The following is an instructional example. Read each statement and identify its input, output, state changes, and failure path.

// math.cpp

int square(int n) { return n * n; }

// main.cpp
#include <iostream>
#include "math.hpp"
int main() { std::cout << square(5) << '\n'; }

Expected behavior: Output 25. Separate the three labeled sections into their respective files.

Q: Why prefer brace initialization? A: It offers consistent initialization syntax and prevents many narrowing conversions.

Q: What is undefined behavior? A: A program execution for which the language standard imposes no requirements; tests passing does not make it valid.

Q: What is the difference between compile and link? A: Compilation translates a translation unit to object code; linking resolves symbols and produces the executable or library.

Q: How do you investigate a crash? A: Reproduce it, preserve exact inputs, build with symbols, inspect the stack in GDB, use appropriate sanitizers, isolate the root cause, and add a regression test.
