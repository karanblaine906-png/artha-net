Basic picture: rule engine vs ML

Traditional programming: input + programmer ke rules → output. ML training: examples (X) + correct answers (y) + algorithm → learned model; inference: new X + learned model → estimated y. Model guarantee nahi deta; distribution shift se predictions fail ho sakte hain.

Teaching analogy

Sochiye ek student ko 1,000 emails diye, har email ke saath "spam" ya "not spam" likha hai. Model word frequencies, senders aur patterns ko weight deta hai. Ye labels ke saath supervised learning hai. Agar label hi na mile aur emails similarities ke basis par groups banaye jaayein, wo unsupervised clustering hai.

ML, DL, AI and GenAI

AI broad field hai—search, logical planning, expert systems bhi AI ho sakte hain. ML data se parameters learn karta hai. Deep Learning (DL) multi-layer neural networks use karta hai. Generative AI text, code, images jaise outputs generate karta; modern GenAI often DL-based hota hai, but "sab AI=GenAI" galat hai.

Batch versus online training

  • Batch: Ek fixed dataset snapshot lo → train → validate → version → deploy. Useful jab labels monthly aate hon.
  • Online/incremental: Naye samples batches/streams mein model update karte hain. partial_fit support model-specific hai. Incremental training ko streaming inference se confuse na karein.
  • Concept drift: Jab real-world relationship badal jaye, jaise spam ke naye styles, model retrain karna pad sakta hai.

End-to-end ML workflow

Machine learning project ka pehla question "kaunsa algorithm?" nahi; "kis outcome ko improve karna hai?" hona chahiye. E.g., SOC alerts ke liye "malicious login detection" ko binary classification frame kar sakte hain, lekin incident labels quality pe depend karega.

 C --> D[Train / validation / test split]
 D --> E[Preprocessing fitted on training only]
 E --> F[Baseline + model]
 F --> G[Threshold & error analysis]
 G --> H[Version & deploy]

Problem-framing checklist

Entity: kaunsa row—user, ticket, transaction? Prediction point: kis time decision liya jayega? Target: label kab available hota hai? Leakage: kya model future ka result dekh raha hai? Cost matrix: false alarm aur missed incident ka cost? Latency: batch hourly or online under 100ms? Ownership: who handles failures?

Module 03: Feature engineering, encoding aur safe pipelines

Playlist entries: 23–34 (listed order). Original playlist: https://www.youtube.com/playlist?list=PLKnIA16_Rmvbr7zKYQuBfsVkjoLcJgxHH

Feature engineering: data ko model-friendly banana

Raw operational logs ko model directly samajhne layak banana padta hai. Aap 2026-10-30T03:02:00 timestamp ko hour, weekday aur weekend indicator mein split kar sakte ho. Naive numeric encoding bhi trap hai: 23:00 aur 00:00 time adjacent hain, par numeric 23 aur 0 distant.

flowchart TD
 A[Raw dataframe] --> B[Train/test split]
 B --> C[ColumnTransformer]
 C --> D[Numeric: median imputer + scaler]
 C --> E[Categorical: most frequent + one hot]
 D --> F[Feature matrix]
 E --> F
 F --> G[Estimator]
 G --> H[Predict/evaluate]

Scale kab zaroori?

Standardization (x-mean)/std, suitable distance and gradient models. MinMaxScaler (x-min)/(max-min) maps training data to range 0..1 but future values can go outside. RobustScaler median/IQR se less sensitive to extreme values. Decision-tree ensembles usually scaling se largely unaffected.

Encoding caveats

Ordinal only meaningful order (low<medium<high). City/department ko 1,2,3 encode karne se false ordering inject hoti hai. OneHotEncoder independent binary columns. Fit vocabulary sirf training set par; production mein unknown labels ke liye handle_unknown='ignore'. Target y labels encode karna distinct problem hai.

Reusable pipeline code

import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression

X = pd.DataFrame({'cpu':[20,90,45,78,33,99],
                  'region':['delhi','delhi','pune','pune','delhi','pune']})
y = [0,1,0,1,0,1]
numeric = Pipeline([('fill', SimpleImputer(strategy='median')),
                    ('scale', StandardScaler())])
category = Pipeline([('fill', SimpleImputer(strategy='most_frequent')),
                     ('encode', OneHotEncoder(handle_unknown='ignore'))])
prep = ColumnTransformer([('num',numeric,['cpu']),('cat',category,['region'])])
model = Pipeline([('prep',prep),('clf',LogisticRegression())])
model.fit(X,y)
print(model.predict_proba(pd.DataFrame({'cpu':[88], 'region':['jaipur']})))

Transformations

Skewed nonnegative count: np.log1p(x) handles zero. Box-Cox input strictly positive; Yeo-Johnson zero/negative handle kar sakta hai. Binning continuous values ko buckets banata hai, but threshold information lose ho sakti. Date-time aur mixed strings ke parsing mein invalid records ko explicitly handle karo.

Leakage-free cross-validation

cross_val_score(model, X, y, cv=...) preprocessing har fold ke training partition par fit karta. Pehle whole dataset pe scaler fit karke baad mein split = data leakage. Similarly feature selection, imputers, target encoding aur SMOTE must happen inside CV folds.

Mini lab: 20 fake records mein 10 missing CPU values, 3 unseen regions aur extreme CPU count include karke same pipeline test karo. fit and transform ka difference write-up karo.

Interview drill: Standard vs Robust scaling? One hot vs ordinal? Why ColumnTransformer? Pipeline ke bina leakage kaise? Why cyclical features need sin/cos?

Module 05: High dimensions aur PCA

Curse of dimensionality

Jab features d grow karte hain, space ka volume fast grow hota. Fixed training samples high-dimensional space ko sparse cover karte: nearest/farthest distance ka contrast weak ho sakta, aur distance-based methods problematic ho jate hain. More features hamesha more predictive nahi.

PCA intuition

Ek tilted cloud of 2D data imagine karo. First Principal Component cloud ke maximum variance direction ko capture karta hai. Dusra perpendicular direction remaining variance. PCA supervised target y ka knowledge nahi use karta; high variance ≠ high predictive importance.

flowchart LR
 A[Numeric training X] --> B[Center; usually standardize]
 B --> C[Covariance / SVD]
 C --> D[Orthogonal components]
 D --> E[Choose n from explained variance]
 E --> F[Project train and unseen samples]

Basic mathematics

Centered matrix Xc: covariance S = XcᵀXc/(n−1). Eigenvectors are principal directions; eigenvalues represent variance along components. Explained ratio of component j is λ_j / Σ λ_i. Scikit-learn typically uses SVD-based variants internally for numerical stability; it doesn't require manual eigendecomposition.

from sklearn.datasets import load_wine
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
X, y = load_wine(return_X_y=True)
p = make_pipeline(StandardScaler(), PCA(n_components=0.95))
Z = p.fit_transform(X)
print('Original:',X.shape,'Projected:',Z.shape)
print('Explained:',p.named_steps['pca'].explained_variance_ratio_.sum())

PCA limitations

PCA components difficult to interpret; categorical one-hot data often deserves other dimension reduction approaches; an unscaled feature with large units dominates. PCA fit inside CV pipeline, never on full dataset before splitting. It may hurt tree models that benefit from original aligned features.

Module 06: Linear regression, metrics aur gradient descent

Playlist entries: 50–60 (listed order). Original playlist: https://www.youtube.com/playlist?list=PLKnIA16_Rmvbr7zKYQuBfsVkjoLcJgxHH

Regression ka intuition

Suppose ghar ka area 600 sqft to price 30 lakh, aur 1000 sqft to 50 lakh. Simple trend y = b0 + b1*x ban sakta hai. Residual e_i=y_i−ŷ_i: actual minus predicted. Ordinary least squares (OLS) minimizes squared residuals.

flowchart LR
 A[Numeric feature x] --> B[Linear prediction: yhat=b0+b1*x]
 B --> C[Compare y vs yhat]
 C --> D[Loss: MSE]
 D --> E[Update coefficients]
 E --> B

Core derivations

For simple regression, b1 = Σ(x−x̄)(y−ȳ)/Σ(x−x̄)², b0 = ȳ−b1*x̄. General regression y≈Xβ; a full-rank solution satisfies β=(XᵀX)⁻¹Xᵀy, but real code should prefer np.linalg.lstsq/QR/SVD, not explicit inverse. Collinearity can make coefficients unstable.

Loss and evaluation metrics: MAE=mean(|y−ŷ|), MSE=mean((y−ŷ)²), RMSE=sqrt(MSE), R²=1−SSE/SST. R² can be negative on test data. Adjusted R² penalizes additional features in ordinary regression settings; not a substitute for held-out evaluation.

Gradient descent from first principles

For J(w,b) = (1/(2n)) Σ(wx_i+b−y_i)², derivative ∂J/∂w = (1/n)Σ(wx_i+b−y_i)x_i; update w←w−η∂J/∂w. Huge learning rate η causes divergence; too low converges slowly. Scaling features improves conditioning.

Batch vs SGD vs mini-batch

Batch: all n samples per step; stable but expensive. SGD: one row each step; noisy but fast updates. Mini-batch: B samples; common for neural networks. A training epoch means approximately each training sample has been used once.

import numpy as np
x=np.array([1.,2.,3.,4.]); y=np.array([3.,5.,7.,9.])
w=0.; b=0.; lr=0.05
for epoch in range(1000):
    error=(w*x+b)-y
    dw=np.mean(error*x); db=np.mean(error)
    w-=lr*dw; b-=lr*db
print('slope=',round(w,3),'intercept=',round(b,3))

Expected approximate output: slope 2, intercept 1. Polynomial regression uses polynomial features x²,x³... but remains linear in parameters; high degree may overfit.

Module 07: Bias-variance aur regularization

Playlist entries: 61–68 (listed order). Original playlist: https://www.youtube.com/playlist?list=PLKnIA16_Rmvbr7zKYQuBfsVkjoLcJgxHH

Why perfect training fit dangerous hai

A model training set ko rote memorize kar sakta hai, par unseen data par fail. Underfitting/high bias: model too simple. Overfitting/high variance: model complexity training noise ko chase karti. Validation curves tune karne mein help karte.

Three penalties

For squared error with coefficient vector w (intercept normally not penalized):

  • Ridge/L2: Loss + α Σ w_j². Coefficients shrink smoothly; exact zero uncommon.
  • Lasso/L1: Loss + α Σ |w_j|. Corners allow zero coefficients; feature selection effect.
  • Elastic Net: Loss + α[r Σ|w_j| + (1−r)/2 Σw_j²] (library scaling conventions vary). Combines L1 and L2.
flowchart TD
 A[Validation high error] --> B{Training error low?}
 B -- Yes --> C[Overfit: regularize, simplify, more data]
 B -- No --> D[Underfit or poor features]
 D --> E[Better features, more expressive model]
 C --> F[Re-evaluate with CV]
 E --> F

Numerical notes

Ridge's gradient on α||w||² contains 2αw (depending on loss normalization). Lasso is non-differentiable at zero; optimizers use coordinate descent or subgradients. Regularize on scaled features so penalty means roughly comparable weight units.

from sklearn.datasets import make_regression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LinearRegression, Ridge, Lasso, ElasticNet
from sklearn.model_selection import cross_val_score
X,y=make_regression(n_samples=250,n_features=25,n_informative=5,
                    noise=20,random_state=42)
for model in [LinearRegression(), Ridge(alpha=10),
              Lasso(alpha=1), ElasticNet(alpha=1,l1_ratio=.5)]:
    p=make_pipeline(StandardScaler(),model)
    mae=-cross_val_score(p,X,y,cv=5,scoring='neg_mean_absolute_error').mean()
    print(type(model).__name__,round(mae,2))

Hyperparameter vs parameter

Model parameters fitted (coef_, tree splits), hyperparameters supplied before fit (alpha, max_depth, C). Increasing Ridge/Lasso alpha means stronger regularization; LogisticRegression C means inverse of regularization strength. Don't confuse!

Module 08: Logistic regression aur classification evaluation

Playlist entries: 69–79 (listed order). Original playlist: https://www.youtube.com/playlist?list=PLKnIA16_Rmvbr7zKYQuBfsVkjoLcJgxHH

Logistic regression: name regression, kaam classification

Linear score z=wᵀx+b ko sigmoid σ(z)=1/(1+e^(−z)) se 0..1 probability estimate banate. Binary target y∈{0,1}. Agar p≥0.5, predict positive, but 0.5 is only a default threshold. Security alerts mein threshold cost-sensitive hona chahiye.

From sigmoid to binary cross-entropy

Individual loss L = −[y log(p)+(1−y) log(1−p)]. Correct confident predictions small loss; confident wrong guesses huge loss. Gradient ∇_w J = Xᵀ(p−y)/n for mean BCE (without penalty). For numerical stability, use trained library loss routines/logsumexp instead of naive np.log at exact 0 or 1.

flowchart LR
 A[Feature vector] --> B[Linear logit z]
 B --> C[Sigmoid p]
 C --> D{Threshold chosen?}
 D -- p >= t --> E[Positive alert]
 D -- p < t --> F[Normal]
 C --> G[BCE training loss]

Confusion matrix

Actual / predicted Pred 0 Pred 1
Actual 0 TN FP
Actual 1 FN TP

Precision=TP/(TP+FP) measures alert purity; Recall=TP/(TP+FN) catches positives; F1=2PR/(P+R) when denominators defined. In a rare-attack SOC case, even 99% accuracy can hide failure if 99% of rows normal. FPR=FP/(FP+TN). Type I error is false positive; Type II is false negative in a hypothesis-testing framing.

Multiclass extension

Softmax probability for class k: exp(z_k)/Σ_j exp(z_j). For numeric stability subtract largest logit before exponentiation. Polynomial features allow nonlinear boundaries though estimator remains linear in transformed features.

    print('threshold:',t,'confusion:',confusion_matrix(yte,(prob>=t).astype(int)).tolist())

flowchart TD
 A[Failed logins > 5?] -->|No| B[Mostly normal]
 A -->|Yes| C{Unusual hour?}
 C -->|No| D[Review]
 C -->|Yes| E[High-risk flag]

Why tree overfits?

Without minimum leaf size/max depth, leaf can memorize single rows. Tune max_depth, min_samples_leaf, ccp_alpha. Trees split axis-aligned: small changes near boundaries can flip outcome.

Bagging and random forests

Bootstrap sample n rows with replacement. Train B base models and average/vote. For reasonably decorrelated estimators, averaging reduces prediction variance. RandomForest adds random candidate feature subsets at each split, reducing tree correlation. n_estimators increases compute, often stabilizes average; max_features, depth and leaf size change bias/variance.

flowchart LR
 A[Train data] --> B[Bootstrap 1]
 A --> C[Bootstrap 2]
 A --> D[Bootstrap N]
 B --> E[Tree 1]
 C --> F[Tree 2]
 D --> G[Tree N]
 E --> H[Average / vote]
 F --> H
 G --> H

OOB (out-of-bag)

Per tree roughly 36.8% of original rows omitted in one size-n bootstrap ((1−1/n)^n≈e^(-1)). OOB samples help estimate generalization for bootstrap ensembles without separate validation set, but do not replace final test set.

Feature importance caution

feature_importances_ impurity-based importance can prefer high-cardinality features; correlated features share importance unpredictably. On validation data, permutation importance measures performance degradation when a column is shuffled. Neither method demonstrates causality.

Boosting, clustering aur meta-learners

Boosting vs bagging

Bagging builds models largely independently on bootstrapped rows; boosting sequentially adds learners to fix weak spots or loss gradients. AdaBoost classical algorithm reweights difficult examples; gradient boosting adds learners to predict loss's negative gradients. Modern implementations include XGBoost, LightGBM, CatBoost (outside lecture scope unless separately studied).

flowchart TD
 A[Initial model F0] --> B[Compute residual / negative gradient]
 B --> C[Fit weak learner h1]
 C --> D[New F = old F + learning_rate*h]
 D --> E{More rounds?}
 E -- Yes --> B
 E -- No --> F[Final boosted model]

Simple gradient boost numeric example

True targets [10,20,30], baseline mean 20, residuals [-10,0,10]. Next weak model learns pattern of residuals. If learning rate 0.1, add only 10% of correction; repeat. Classification uses derivatives of classification loss (e.g. log loss), not just raw y-p without nuance.

K-means: center-based clustering

For K clusters, assign each point to nearest centroid (typically Euclidean distance), recompute centroid as mean, repeat. Objective is within-cluster squared distances (inertia_): smaller with K usually, so compare K via elbow, silhouette plus domain relevance. K-means assumes compact roughly spherical clusters, scale-sensitive, needs K.

flowchart LR
 A[Choose K centroids] --> B[Assign nearest center]
 B --> C[Recompute group means]
 C --> D{Centroids stable?}
 D -- No --> B
 D -- Yes --> E[Cluster assignments]

Hierarchical clustering

Agglomerative starts with every sample as own cluster, merges closest groups until target count. Linkage matters: single/min, complete/max, average, Ward/minimize cluster variance. Dendrogram cut level sets cluster granularity.

Stacking / blending

Base models outputs become features for meta-model. Training meta-model on same rows' in-sample predictions leaks target and overfits; use out-of-fold predictions (StackingClassifier handles CV) or true hold-out blend set.

KNN, SVM and probabilistic classifiers

K-nearest neighbors (KNN)

No explicit coefficients: during prediction, identify k nearest training samples. For classification majority/weighted vote; regression neighbor mean. Small k unstable, large k too smooth. Crucial: distances depend on scale; StandardScaler usually beneficial. Memory and prediction time grow with training data.

Support Vector Machine (SVM)

For separable classes, maximize margin—distance from separating hyperplane to closest training examples (support vectors). Hard margin assumes perfectly separable data; soft margin allows violations via slack variables ξ_i and penalty parameter C. Larger C penalizes violations more (can overfit). With RBF kernel, gamma controls locality; high gamma potentially narrow/complex boundary. Scale before SVM.

flowchart TD
 A[Classification dataset] --> B{Boundary type?}
 B -- Local neighborhood --> C[KNN + scaler]
 B -- Wide-margin boundary --> D[SVM + scaler]
 B -- Probabilistic simple baseline --> E[Naive Bayes]
 D --> F[Kernel? linear / RBF]
 C --> G[Cross-validation]
 F --> G
 E --> G

Conditional probability and Bayes

P(A|B)=P(A∩B)/P(B). Bayes' rule P(C|x)=P(x|C)P(C)/P(x). Prior P(C) is base rate, likelihood P(x|C) says data compatibility, posterior updated class probability. Mutually exclusive is not independent: for disjoint positive-probability events, intersection zero but product nonzero.

Naive Bayes independence assumption

Assumes features conditionally independent given class: P(x1,..,xd|C)≈Π_j P(xj|C). May be violated but classifier can still perform well. GaussianNB for continuous approximate gaussian features; MultinomialNB for nonnegative counts (text token counts); BernoulliNB binary occurrences. Use log-probabilities to avoid underflow.

Module 12: XGBoost, DBSCAN, imbalance, Optuna aur ROC

Playlist entries: 127–134 (listed order). Original playlist: https://www.youtube.com/playlist?list=PLKnIA16_Rmvbr7zKYQuBfsVkjoLcJgxHH

Advanced toolbox and honest limits

XGBoost overview

Gradient boosted decision tree framework with objectives combining data-fit loss and model complexity regularization. Typical derivation approximates loss with first and second order gradients (g,h). Candidate split gain compares leaf-score improvement with regularization; XGBoost handles missing branches natively. Learn early stopping, learning rate, tree depth, row/feature sampling, reg_alpha, reg_lambda, and proper validation.

Gradient boosting vs XGBoost

Both sequential decision-tree models, but XGBoost provides optimized training algorithms, regularization knobs and split handling. Different implementations can lead to different results even on same data. No external or paid GPU required for small tabular demos.

DBSCAN density clustering

DBSCAN groups points connected through dense neighborhoods defined by eps radius and min_samples. Core points have sufficient neighbors, border points connect to core, noise points label -1. Can find nonconvex shapes unlike KMeans, but varying densities and high dimensions complicate eps tuning.

flowchart TD
 A[Tabular classification with rare positives] --> B[Stratified train/validation/test]
 B --> C[Preprocessing fit on train]
 C --> D[Class-weight / resampling inside training folds]
 D --> E[Optuna tuning against validation objective]
 E --> F[Choose threshold on validation]
 F --> G[One-time test evaluation]
 G --> H[Deploy + monitor precision-recall/drift]

Imbalanced data: avoid dangerous shortcuts

At 1% positive rate, accuracy 99% if predict all negatives! Focus PR-AUC/average precision, recall at acceptable precision, cost matrix, and calibration. SMOTE synthesizes minority samples; do not SMOTE before train/test split or before CV split (leakage). Prefer imblearn.pipeline.Pipeline for fold-scoped oversampling. Group/time data may make SMOTE unsuitable.

ROC and PR curves

ROC plots TPR (recall) against FPR across thresholds. ROC-AUC summarizes ranking quality; with tiny positive prevalence, ROC-AUC can look reassuring despite poor precision. Precision-recall curve more informative for low base rates. AUC is not one threshold's accuracy.

Hyperparameter tuning with Optuna

Study proposes parameter trials; each trial fits model and returns validation score. Use reproducible seed, limited budget, parallelism carefully, and final held-out test. Optuna library optional; baseline RandomizedSearchCV works with scikit-learn only.

Appendix A: Self-contained practice projects

Project 1: SOC unusual-login detector

Goal: Historical per-user login behavior se high-risk login event score. Features: failed attempts last 60 minutes, new device indicator, unusual hour (respect local time and cyclical encoding), unique IP count. Label: confirmed malicious/legitimate with source/time provenance. Flow: Define prediction timestamp → join past-only data → group/time-aware split → baseline → validation PR curve → threshold chosen from operational alert budget → shadow mode → production monitoring. Important: class imbalance, alert fatigue, concept drift, privacy, group leakage; dangerous automated blocking bina human review avoid karo.

Project 2: Cloud capacity forecasting

Goal: Future CPU/load forecast. Features: lagged CPU, hour-of-day sin/cos, seasonality, event labels. Validation: temporal folds, not random. Baseline: previous hour value. Metric: MAE/RMSE plus cost-weighted underprediction. Do not: include future rolling averages in features.

Project 3: Customer service ticket triage

Goal: Predict priority; mixed text/categories/numeric features. Guardrail: sensitive info handling; categorical pipeline; macro F1 not just accuracy; final manual review. Deploy: versioned preprocessing and prediction schema, drift monitoring.
