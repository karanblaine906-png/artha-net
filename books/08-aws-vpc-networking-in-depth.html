You may have:

8.4 Routing Is the Foundation

Before studying advanced AWS networking, remember:

SOURCE
   |
   v
ROUTE TABLE
   |
   v
TARGET
   |
   v
DESTINATION

A connection requires a valid path in both directions.

A common mistake is to check only the forward route.

8.5 Forward and Return Path

Example:

VPC-A
10.10.0.0/16

to:

VPC-B
10.20.0.0/16

Forward:

10.10.0.0/16
      |
      v
10.20.0.0/16

Return:

10.20.0.0/16
      |
      v
10.10.0.0/16

If the return route is missing, communication fails even when the forward route exists.

8.6 Longest Prefix Match

Suppose a route table contains:

10.0.0.0/8       -> Transit Gateway
10.20.0.0/16     -> VPC Peering
0.0.0.0/0        -> NAT Gateway

Destination:

10.20.15.25

The most specific matching route is:

10.20.0.0/16

Therefore the peering route is selected.

8.7 Route Specificity

More specific:

/24

beats:

/16

which beats:

/8

which beats:

/0

This simple concept explains many AWS routing decisions.

8.8 VPC Peering

VPC Peering provides private connectivity between two VPCs.

Architecture:

VPC-A
10.10.0.0/16
    |
    v
VPC Peering
    |
    v
VPC-B
10.20.0.0/16

Traffic uses private IP connectivity.

8.9 VPC Peering Requirements

For communication, typically you need:

Peering connection
Route in VPC-A
Route in VPC-B
Security Group permissions
NACL permissions
Application listener
DNS configuration where required

Creating the peering connection alone is not enough.

8.10 Peering Route Example

VPC-A route:

Destination:
10.20.0.0/16

Target:
pcx-xxxxxxxx

VPC-B route:

Destination:
10.10.0.0/16

Target:
pcx-xxxxxxxx

Now both sides know how to reach each other.

8.11 VPC Peering Is Non-Transitive

Suppose:

VPC-A <----> VPC-B <----> VPC-C

This does not automatically mean:

VPC-A <----> VPC-C

VPC Peering is not transitive.

This is one of the most important interview points.

8.12 Non-Transitive Example

Connections:

A-B = Peered
B-C = Peered

Desired:

A -> B -> C

VPC Peering does not turn B into a transit router for A and C.

For many-VPC connectivity, Transit Gateway is often a better architecture.

8.13 Peering Mesh Problem

With only two VPCs:

A <--> B

simple.

With five VPCs:

A
|\ \
| \ \
B--C--D--E

Full-mesh peering becomes operationally complex.

The number of possible pairwise relationships grows rapidly.

8.14 Transit Gateway

AWS Transit Gateway provides a central routing hub for connecting VPCs and supported external networks.

Concept:

             VPC-A
               |
               v
             +-----+
VPC-B ------>| TGW |<------ VPC-C
             +-----+
               ^
               |
          On-Premises

TGW simplifies many-to-many connectivity.

8.15 Hub-and-Spoke Model

Transit Gateway commonly enables:

              HUB
              TGW
        /      |      \
       /       |       \
      v        v        v
   PROD      DEV     SHARED

Each VPC is a spoke.

Benefits:

Centralized routing
Simpler topology
Scalable connectivity
Network segmentation
Hybrid connectivity

8.18 Transit Gateway Route Table

TGW has its own routing domain.

Example:

Destination        Attachment

10.10.0.0/16       prod-vpc
10.20.0.0/16       dev-vpc
10.30.0.0/16       shared-vpc
172.16.0.0/16      vpn

This is separate from each VPC's route table.

8.19 Two Routing Layers

When using TGW, reason through:

VPC Route Table
       |
       v
Transit Gateway
       |
       v
TGW Route Table
       |
       v
Destination Attachment
       |
       v

8.20 Transit Gateway Association

A TGW attachment can be associated with a TGW route table.

Concept:

Attachment
    |
    v
TGW Route Table

Association determines which TGW route table is used for traffic entering from that attachment.

      |

8.22 TGW Segmentation

You may not want all VPCs to communicate.

Example:

Production
    X
Development

TGW route tables can help create segmented routing domains.

8.23 Segmented Architecture

          Shared Services
                |
                v
               TGW
             /     \
            /       \
           v         v
        PROD         DEV

Routing can be designed so:

PROD -> SHARED = Allowed
DEV  -> SHARED = Allowed
PROD -> DEV    = Not routed
DEV  -> PROD   = Not routed

This is powerful for enterprise network isolation.

8.58 IPv6 in Amazon VPC

IPv6 uses 128-bit addresses.

Example:

2001:db8::/32

AWS VPCs can support IPv6 addressing and dual-stack architectures.

IPv6 changes important networking assumptions.

8.59 IPv6 Does Not Use NAT in the Same Way as IPv4

A key IPv6 concept is globally unique addressing.

Do not design IPv6 merely by copying an IPv4 NAT architecture.

Security is provided through routing and filtering rather than assuming NAT equals security.

8.117 Common Mistakes

  1. Assuming VPC Peering is transitive.
  2. Creating TGW attachment but forgetting VPC routes.
  3. Configuring VPC routes but forgetting TGW routes.
  4. Missing return routes.
  5. Overlapping CIDRs.
  6. Treating VPN tunnel UP as proof of application connectivity.
  7. Advertising wrong prefixes with BGP.
  8. Ignoring hybrid DNS.
  9. Using full VPC connectivity when only one service is required.
  10. Forgetting interface endpoint Security Groups.
  11. Assuming endpoint policy replaces IAM.
  12. Treating Flow Logs as packet capture.
  13. Assuming ACCEPT means application success.
  14. Ignoring IPv6 rules.
  15. Using IPv4-only security rules in dual-stack designs.
  16. Forgetting egress-only IGW for appropriate IPv6 outbound-only patterns.
  17. Centralizing egress without designing return paths.
  18. Creating asymmetric routing through stateful firewalls.
  19. Ignoring AZ dependencies.
  20. Deploying one Direct Connect path and calling it highly available.
  21. Making route tables too broad.
  22. Not documenting CIDR ownership.
  23. Forgetting DNS when IP connectivity works.
  24. Changing multiple network controls at once during incidents.
  25. Opening 0.0.0.0/0 to "test" without understanding the risk.

8.119 Interview Questions --- VPC Peering

Q1. Is VPC Peering transitive?

No.

If:

A peers with B
B peers with C

A does not automatically reach C through B.

Q2. What is required after creating a peering connection?

Typically:

Accept peering
Configure routes
Configure Security Groups
Configure NACLs if necessary
Configure DNS as required
Verify application listener

8.120 Interview Questions --- Transit Gateway

Q3. Why use Transit Gateway?

To provide scalable centralized routing between multiple VPCs and supported hybrid network connections.

Q4. What are the two routing layers with TGW?

VPC route table
TGW route table

Both must be correct.

Q5. Can TGW isolate production from development?

Yes, routing segmentation can be implemented using Transit Gateway route-table architecture.

8.121 Interview Questions --- Hybrid

Q6. VPN vs Direct Connect?

Site-to-Site VPN commonly uses encrypted IPsec connectivity over internet/network paths.

Direct Connect provides dedicated connectivity to AWS.

Many enterprises use both in resilient hybrid designs.

Q7. What is BGP used for?

Dynamic exchange of network reachability information.

Q8. Tunnel is UP but application is unreachable. What do you check?

Routes

On-prem firewall
Return path
DNS

8.122 Interview Questions --- DNS

Q9. AWS instance can reach on-prem by IP but not hostname. What is likely wrong?

Focus on DNS.

Check:

Resolver rules
Outbound Resolver endpoint
On-prem DNS
Network path to DNS
Security controls

Q10. What is a Resolver inbound endpoint?

It allows DNS queries from external networks such as on-premises environments to enter Route 53 Resolver for applicable AWS private DNS resolution.

8.123 Interview Questions --- PrivateLink

Q11. PrivateLink vs VPC Peering?

Peering connects networks.

PrivateLink exposes specific services privately through endpoint architecture.

Q12. Why might PrivateLink be more secure for a shared service?

Because consumers can access the exposed service without requiring broad routed connectivity to the provider VPC.

8.124 Interview Questions --- IPv6

Q13. What is the IPv6 default route?

::/0

Q14. What is an Egress-only Internet Gateway?

A VPC component that supports outbound-initiated IPv6 internet connectivity while preventing unsolicited inbound connections through that route.

Q15. Does NAT Gateway solve IPv6 private egress in the same way as IPv4?

No. IPv6 architecture is different; egress-only IGW is one AWS mechanism for outbound-only IPv6 internet connectivity.
