01. Python Foundations — language ko zero se samjho

Concept

Computer ko instructions dene ke liye Python ek high-level programming language hai. Program instructions ka sequence hota hai; interpreter code run karta hai; variables values ko names dete hain; objects runtime mein values represent karte hain. Python mein x = 10 ek name ko integer object se bind karta hai — fixed-size memory box samajhna sirf beginner analogy hai.

  • int whole number, float decimal, bool True/False, str text, None absence-of-value marker.
  • print() output deta hai; input() string return karta hai (number chahiye toh int()/float() lagao, validate karo).
  • == value compare; is identity compare. = assign karta hai.
  • if/elif/else branching; for iterable par loop; while condition tak; break stop, continue skip.
  • Mutable (list, dict, set) contents badal sakte; immutable (int, str, tuple) nahi.
name = 'Asha'
age = 20
salary = 35000.0
eligible = age >= 18 and salary > 0
print(f'{name}: eligible={eligible}')

marks = [45, 89, 67, 72]
for mark in marks:
    if mark >= 60:
        print('Pass with >=60:', mark)

answer = sum(marks) / len(marks)
print('Average:', answer)

Logic workflow

flowchart TD
    A[Input: student marks] --> B{Any marks?}
    B -- No --> C[Error: empty list]
    B -- Yes --> D[Calculate average]
    D --> E{Average >= 60?}
    E -- Yes --> F[Distinction band]
    E -- No --> G[Keep practicing]

Strings and loops

Strings Unicode text hoti hain. Indexing zero se (s[0]) aur slicing [start:stop:step] mein stop exclude hota hai. strip() spaces remove, .lower() case normalization, .split() tokenization, ' '.join(...) string build karte hain. range(5) = 0..4. enumerate(items) index+value; zip(a,b) matching pairs.

text = '  Data Science  '
print(text.strip().lower())
for i, ch in enumerate('ML'):
    print(i, ch)
for n in range(1, 6):
    print(n, n * n)

Time complexity ka intuition

Agar 10 items mein search ko 10 comparisons chahiye aur 1000 items mein 1000, linear O(n). Binary search sorted input par O(log n) (magar sorting cost count karo). Nested full loops roughly O(n²). Time complexity hardware timer nahi, input size ke saath growth explain karti hai.

Common mistakes: if x = 5 syntax error (use ==), input() string ko integer samajhna, range ke end ko inclusive samajhna, empty list se mean nikalna, is use for numeric/string equality.

Practice: (1) list ke even numbers count karo; (2) palindrome check; (3) vowel frequencies; (4) positive numbers ka average; (5) 2 nested loops ki complexity explain.

Interview Q: Q: is vs ==? A: == checks equality of values; is object identity. Q: Mutable defaults issue? A: Default [] shared between function calls; use None then create list.

02. Data Structures, Functions, OOP and Robust Code

Collections

  • List [1,2,3]: ordered, mutable, duplicate allowed; append, pop, slice.
  • Tuple (1,2): ordered, immutable sequence; fixed record-like values.
  • Set {1,2}: unique members, no positional indexing; membership and set algebra.
  • Dict {'name':'Ravi'}: key→value mapping; average membership lookups efficient.
sales = [{'city':'Delhi','value':120}, {'city':'Pune','value':80}, {'city':'Delhi','value':50}]
by_city = {}
for record in sales:
    city = record['city']
    by_city[city] = by_city.get(city, 0) + record['value']
print(by_city)  # {'Delhi': 170, 'Pune': 80}

Functions / scope

Functions reusable blocks hain. Argument input, return output. Local variable usually function ke scope mein. *args positional bundle; **kwargs keyword bundle. Pure function ko same inputs par same outputs milte hain aur external state modify nahi hota — easier testing.

def safe_mean(values):
    if not values:
        raise ValueError('At least one value required')
    return sum(values) / len(values)

try:
    print(safe_mean([1,2,3]))
except ValueError as exc:
    print('Invalid input:', exc)

OOP

Class blueprint, instance actual object; __init__ initial attributes. Encapsulation related state/behaviour group, inheritance share/extend behavior, polymorphism same interface on different types. @property controlled access, @staticmethod no instance needed. Composition is often simpler than deep inheritance.

class BankAccount:
    def __init__(self, starting_balance=0):
        if starting_balance < 0:
            raise ValueError('Negative starting balance')
        self._balance = float(starting_balance)

    @property
    def balance(self):
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError('Deposit must be positive')
        self._balance += amount

account = BankAccount(100)
account.deposit(50)
print(account.balance)

Advanced Python

Iterator provides next item one at a time; generator uses yield, useful when full dataset doesn't fit RAM. Decorator wraps another function (e.g. timing/logging) without rewriting it. Context manager with open(...) closes files even after exceptions. Serialization saves data (CSV, JSON, pickle); untrusted pickle unsafe, prefer JSON for simple interoperable data.

import json
from pathlib import Path
path = Path('config.json')
path.write_text(json.dumps({'threshold': 0.7}), encoding='utf-8')
config = json.loads(path.read_text(encoding='utf-8'))
print(config['threshold'])

def squares():
    for n in range(5):
        yield n * n
print(list(squares()))

flowchart LR
    A[Raw input] --> B[Validation function]
    B --> C[Business logic / class]
    C --> D[Exception handling]
    D --> E[JSON or CSV output]

Common issues: KeyError unknown key → dict.get; IndexError wrong position → check length; TypeError wrong argument type; FileNotFoundError → pathlib absolute/relative check; UnicodeDecodeError → explicit encoding; RecursionError → incorrect base case.

Practice: Build expense tracker with add, summarize, export JSON. Add unit tests for invalid negative amounts. Interview: Generator vs list? Generator lazy, usually memory efficient; list materializes all items.

03. NumPy — vectorized numerical computing

Why NumPy?

Python list diverse objects store kar sakti, isliye numeric loops costly ho sakte. NumPy ndarray mostly homogeneous elements ko compact shape/dtype ke saath stores. Vectorized operations compiled code use karte, often much faster. shape=(rows, cols), ndim axis count, dtype element type, axis=0 down rows across each column, axis=1 across columns for each row.

import numpy as np
scores = np.array([[70, 80, 90], [50, 60, 70]], dtype=float)
print('shape', scores.shape)            # (2, 3)
print('student means', scores.mean(axis=1))
print('subject means', scores.mean(axis=0))
print(scores[:, 1])                    # column 2
print(scores[scores >= 70])            # boolean indexing

Broadcasting rules

Dimensions compare right-to-left. Do dimensions compatible hain jab equal ho ya ek 1 ho; warna ValueError. (2,3) + (3,) works; (2,3) + (2,) nahi. Shapes strategically reshape(-1,1) se align karo.

prices = np.array([[100, 200, 300], [400, 500, 600]])
tax_rate = np.array([0.05, 0.12, 0.18])
final_prices = prices * (1 + tax_rate)
print(final_prices)

Math to ML bridge

Sigmoid 1/(1+exp(-x)) scores ko (0,1) mein squash karta hai; probability interpretation only when model appropriate/calibrated. MSE = average squared errors; standardized features z=(x-mean)/std. Overflow se bachne ke liye large x par stable sigmoid implementations use hoti hain.

x = np.array([-2., 0., 2.])
sigmoid = 1 / (1 + np.exp(-x))
y_actual = np.array([10., 20., 30.])
y_pred = np.array([12., 19., 28.])
mse = np.mean((y_actual - y_pred) ** 2)
print(sigmoid, mse)

flowchart LR
    A[2D array: shape 2 x 3] --> B[Broadcast vector: shape 3]
    B --> C[Elementwise operation]
    C --> D[Output: shape 2 x 3]

Pitfalls: a * b = elementwise multiplication; a @ b = matrix multiplication; integer arrays cannot hold np.nan; avoid Python truth tests if array:; use .any()/.all().

Lab: labs/02_numpy_operations.py; change axis and shape, predict output before running. Interview: view vs copy? View may share underlying memory; copy allocates independent data. Check .base/np.shares_memory().

04. Pandas — tables, joins, groupby and time series

Series vs DataFrame

Series labeled 1-dimensional data; DataFrame columns with shared index, table jaisa. .loc[row_label, col_label] label-based, .iloc[row_position, col_position] positional. Missing values NaN/pd.NA handle with isna, imputation, drop only after considering bias. Avoid row-wise Python loops; vectorized operations faster.

import pandas as pd
orders = pd.DataFrame({
    'city':['Delhi','Pune','Delhi','Mumbai','Pune'],
    'revenue':[100,200,150,None,300],
    'units':[1,2,1,3,2]
})
print(orders.info())
orders['revenue'] = orders['revenue'].fillna(orders['revenue'].median())
orders['unit_price'] = orders['revenue'] / orders['units']
print(orders.groupby('city', as_index=False)['revenue'].sum())

Joins

merge SQL join equivalent, but duplicates on keys can create many-to-many row explosions. Use validate='many_to_one' where appropriate. concat rows/columns stack karta; pivot_table summarize & reshape; melt wide → long. to_datetime date parse, .dt extracts year/month, .resample('MS') time buckets (DatetimeIndex needed).

customers = pd.DataFrame({'city':['Delhi','Pune','Mumbai'], 'region':['N','W','W']})
with_region = orders.merge(customers, on='city', how='left', validate='many_to_one')
print(pd.pivot_table(with_region, index='region', values='revenue', aggfunc='sum'))

flowchart TD
    A[CSV / API / DB] --> B[read_csv / read_json / read_sql]
    B --> C[info + describe + isna]
    C --> D[Clean columns / deduplicate]
    D --> E[merge + groupby + pivot]
    E --> F[Charts / ML features / export]

Pitfalls: chained assignment like df[df.x>0]['x']=... use .loc; dropping missing values blindly loses signal; .apply(axis=1) very large tables par slow; merge duplicates wrongly inflate totals. Validate unique key, compare before/after row counts.

Practice: CSV se monthly revenue, top 3 cities, missing rate, repeat customer rate. Interview: groupby vs pivot_table? Both aggregation; pivot creates wide cross-tab layout conveniently. Lab: labs/03_pandas_eda.py.

06. Data Gathering, ETL, Cleaning and Exploratory Data Analysis

ETL / data quality

Extract source se read (CSV/DB/API), Transform types, dedup, null repair, normalizations, Load destination table. Data science mein raw data preserved rakho to be reproducible. EDA = Exploratory Data Analysis — pehle dataset ka story samjho; model banana second step.

flowchart TD
    A[Original source] --> B[Raw snapshot: immutable]
    B --> C[Schema + quality checks]
    C --> D[Cleaning: types / duplicates / invalid]
    D --> E[EDA: summary + plots]
    E --> F[Feature plan]
    F --> G[Train/test split]
    G --> H[Model]

Checklist

  1. Grain: one row actually represents what? one customer? one order? one transaction?
  2. Types: currency numeric? date parsed? categorical consistently spelled?
  3. Missingness: MCAR/MAR/MNAR mechanisms; missing itself can be signal.
  4. Duplicates: true duplicates vs legitimate repeated purchases; choose key carefully.
  5. Outliers: wrong measurement or legitimate extreme? Domain check before removal.
  6. Leakage: future information accidentally features mein toh nahi?
  7. Privacy: emails/phone numbers/identifiers minimize, protect, never put in public repo.

Simple reproducible cleaning

import pandas as pd
raw = pd.DataFrame({
  'order_id':[1,1,2,3], 'amount':['120','120','bad','300'],
  'date':['2026-01-01','2026-01-01','2026-01-02','2026-01-03']
})
clean = raw.drop_duplicates(subset='order_id').copy()
clean['amount'] = pd.to_numeric(clean['amount'], errors='coerce')
clean['date'] = pd.to_datetime(clean['date'], errors='coerce')
print(clean.isna().sum())

Important: Bad numeric data coerced to NA; replace with median only when justified (for analyses/ML), otherwise flag for review. Practice: Calculate missing percentage, duplicate count, before/after row count; write a log. Lab: labs/03_pandas_eda.py.

07. Relational Databases & SQL from Beginner to Window Functions

Core model

Database data organized store; table rows/columns; primary key unique identifier; foreign key another table reference. DDL (CREATE, ALTER), DML (INSERT, UPDATE, DELETE), DQL (SELECT). Transactions BEGIN/COMMIT/ROLLBACK and ACID principles. Normalization reduces duplication; denormalization sometimes read performance ke liye deliberate.

CREATE TABLE customers(id INTEGER PRIMARY KEY, city TEXT NOT NULL);
CREATE TABLE orders(id INTEGER PRIMARY KEY, customer_id INTEGER, amount REAL,
  FOREIGN KEY(customer_id) REFERENCES customers(id));

SELECT c.city, COUNT(*) AS orders, SUM(o.amount) AS total
FROM orders AS o
JOIN customers AS c ON o.customer_id = c.id
GROUP BY c.city
HAVING SUM(o.amount) > 100
ORDER BY total DESC;

JOINs

INNER matched; LEFT all left + matched right; RIGHT supported in many databases; FULL OUTER both sides (check DB support). Joining on nonunique keys can multiply records; test keys, schema, null behavior.

Subqueries and windows

Subquery result nested SQL mein use; window function rows ko collapse nahi karti (unlike GROUP BY) and can rank/running total within partitions.

SELECT customer_id, amount,
       ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY amount DESC) AS rank_in_customer,
       SUM(amount) OVER (PARTITION BY customer_id) AS customer_total
FROM orders;

flowchart LR
    A[FROM + JOIN] --> B[WHERE row filter]
    B --> C[GROUP BY]
    C --> D[HAVING group filter]
    D --> E[SELECT + windows]
    E --> F[ORDER BY / LIMIT]

Conceptual SQL evaluation order, not a promise about database execution-plan order.

Pitfalls: WHERE amount = NULL wrong; use IS NULL; query grouping nonaggregated columns nonportable; injection risk → parameterized queries (never f-string SQL with raw user values). SQL is set-based, not procedural loop. Lab: labs/04_sqlite_analysis.py creates DB in memory and runs queries, no server needed.

08. Descriptive Statistics, Probability and Distributions

Statistics ka role

Population complete set; sample subset. Descriptive statistics available observations summarize karta; inferential sample se broader uncertainty quantify. Center: mean, median, mode. Spread: variance, standard deviation, IQR. Mean outliers se sensitive; median relatively robust.

Example: salaries [20,22,24,25,200] (thousand) mein mean 58.2, median 24. Ek CEO salary ne mean bahut pull kiya — salary discussion ke liye median often better.

Formulas: mean = Σx/n. Population variance = Σ(x-μ)²/N; sample variance = Σ(x-x̄)²/(n-1) (unbiased population variance estimator under standard assumptions). Standard deviation = square root of variance. Z-score = (x-μ)/σ if σ nonzero. Percentile = relative position in a distribution; quantile implementation differs slightly across libraries.

Probability

Events A, B. P(A|B)=P(A∩B)/P(B) for nonzero P(B). Bayes theorem P(A|B)=P(B|A)P(A)/P(B). Independent events: P(A∩B)=P(A)P(B); mutually exclusive events with nonzero probabilities are not independent.

  • Bernoulli: one yes/no trial (p). Binomial: successes in fixed independent Bernoulli trials.
  • Normal/Gaussian: bell-shaped continuous distribution defined by mean and standard deviation.
  • Poisson: events in interval under assumptions of constant rate and independence.
  • Exponential: waiting time of Poisson process.
  • PMF: probability mass at discrete values, PDF: density (not probability at a point), CDF: probability P(X≤x).
import numpy as np
values = np.array([20, 22, 24, 25, 200])
print('mean:', values.mean(), 'median:', np.median(values))
print('sample standard deviation:', values.std(ddof=1))

flowchart TD
    A[Raw numeric data] --> B{Question?}
    B -- Typical value --> C[Mean / median]
    B -- Spread --> D[Std / IQR]
    B -- Uncertainty --> E[Distribution / sampling]
    E --> F[Inference]

Interviews: (1) Why ddof=1? sample variance Bessel correction. (2) Correlation vs causation? correlation measures association; confounding/reverse causation possible. (3) PDF vs CDF? density vs cumulative probability. Practice: write a function computing mean/median/std and compare with NumPy. Lab: labs/05_stats_tests.py.

09. Inferential Statistics: CLT, Confidence Intervals, Hypothesis Tests

Central Limit Theorem (CLT)

Independent identically distributed samples with finite variance and sufficiently large n mein sample mean ka standardized distribution approximately normal hota hai (many generalizations exist). CLT original data ko normal nahi banata; repeated sample means ki distribution approach hoti hai. Skewness/heavy tails large sample requirement badha sakte hain.

Confidence interval

Agar population SD known or approximation justified, mean ke liye approximate 95% CI x̄ ± 1.96 × SE; SE = σ/√n (unknown σ cases mein t critical / estimated SE). Correct frequency interpretation: repeated experiment procedure ke 95% intervals true parameter cover karenge; ek fixed interval mein 95% probability of parameter statement frequentist framing mein nahi.

Hypothesis testing workflow

flowchart TD
    A[Define research question] --> B[H0 and H1]
    B --> C[Select test + check assumptions]
    C --> D[Choose alpha before viewing result]
    D --> E[Compute statistic + p-value]
    E --> F{p <= alpha?}
    F -- Yes --> G[Reject H0]
    F -- No --> H[Fail to reject H0]
    G --> I[Report effect size + CI + limitations]
    H --> I

H0 null statement; H1 alternative. p-value = probability under H0 of data at least as extreme as observed, according to the chosen test, not probability H0 is true. α=0.05 false positive long-run threshold when H0 true; Type I = reject true H0; Type II = fail to reject false H0. Power = 1-β.

Situation Common test (assumptions apply)
One sample mean One-sample t-test
Two independent means Welch t-test
Paired before/after Paired t-test
Categorical association Chi-square test
More than two group means ANOVA 
from scipy import stats
before = [10, 12, 11, 14, 13, 10]
after  = [11, 14, 13, 15, 14, 12]
result = stats.ttest_rel(after, before)
print('statistic=', result.statistic, 'p=', result.pvalue)

Pitfalls: significance ≠ practical importance; non-significance ≠ equality; many repeated tests inflate false positives; peeking at A/B tests can break naive p-value interpretation; data dependence may invalidate test. Practice: write hypotheses and test choice for (a) paired weight measurements, (b) city vs product type, (c) three teaching methods.

10. Linear Algebra & Calculus for ML

Shapes matter more than memorizing formulas

Scalar: 3; vector: [1,2]; matrix: rows and columns; tensor: generalized multidimensional array. ML mein dataset X shape (n_samples, n_features) aur target y usually (n_samples,).

Dot product a·b=Σaᵢbᵢ projection / similarity / linear model score mein use. Matrix multiplication X @ w: (n,p)@(p,)→(n,). Transpose X.T flips axes. Eigenvector direction jo square linear transform ke baad same line par rehta hai; eigenvalue us direction ka scaling. PCA covariance matrix ki eigenvectors ko principal directions ke roop mein use karta (implementation often SVD).

import numpy as np
X = np.array([[1., 2.], [3., 4.], [5., 6.]])
w = np.array([0.5, -0.25])
b = 2.
prediction = X @ w + b
print(prediction)

Derivative intuition

Derivative slope/instantaneous rate of change hai. f(w)=(w-3)² has derivative f'(w)=2(w-3); when w<3, derivative negative so subtracting derivative moves w upward, toward minimum. Chain rule composite functions ka derivative: d f(g(x))/dx = f'(g(x))g'(x).

flowchart LR
    A[Features X] --> B[Linear combination Xw+b]
    B --> C[Prediction]
    C --> D[Loss against y]
    D --> E[Derivative / gradient]
    E --> F[Update parameters]
    F --> B

Math basics revision: vectors, dot product, matrix multiplication, rank, eigen decomposition, partial derivative, gradients. Pitfalls: (n,) and (n,1) broadcast differently; A*B is not A@B; inv(X.T@X) may fail for singular matrices. Prefer numerically stable solvers/pseudoinverse. Interview: What is gradient? Vector of partial derivatives, direction of steepest local increase in Euclidean coordinates.

11. Machine Learning Fundamentals & Linear Regression

What is ML?

Traditional software mein human rules likhta, ML mein algorithm labeled/unlabeled examples se patterns estimate karta. Supervised learning has labels (regression numeric, classification class). Unsupervised learning explores structure without external labels (clusters, dimension reduction). Training is optimization; testing unseen data par generalization measure karta.

Model ŷ = w₀ + w₁x₁ + ⋯ + wₚxₚ. Simple linear regression one feature; multiple linear regression several. w₀ intercept; coefficients conditional linear effects for fixed other features (not causal automatically). MSE 1/n Σ(yᵢ-ŷᵢ)²; MAE robust-ish against large outliers compared to MSE; R² relative fit versus predicting sample mean (can be negative on test data).

import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score
X = np.array([[1],[2],[3],[4],[5]], dtype=float)
y = np.array([3.,5.,7.,9.,11.])
model = LinearRegression().fit(X[:4], y[:4])
pred = model.predict(X[4:])
print('coefficient=', model.coef_, 'intercept=', model.intercept_)
print('MAE=', mean_absolute_error(y[4:], pred), 'R2 requires 2+ test points')

Train/test split

Test set model development ke baad final honest evaluation ke liye; train pe best score misleading. Random splits for i.i.d. problems; time series mein chronological split (future past train ko predict kare); group data mein GroupKFold/GroupShuffleSplit avoid same customer in train and test.

flowchart LR
    A[Available labeled examples] --> B[Split train / test]
    B --> C[Fit preprocessing on train]
    C --> D[Train model]
    D --> E[Validation: choose model]
    E --> F[Final untouched test]
    F --> G[Deployment & monitoring]

Practice: Build house-price regression, choose MAE because rupee errors interpretable; then compare MSE. Pitfalls: fit_transform() whole dataset before split causes leakage; extrapolating linear relationship outside observed range risky. Lab: labs/06_gradient_descent.py compares manual regression to sklearn.

12. Gradient Descent: learning ka engine

Why optimization?

Linear regression loss minimize karna hai. Gradient (derivative) slope batata, step size learning_rate decide karta kitni jaldi move karna: w_new = w_old - η∇L(w_old).

For prediction ŷ = wx+b and MSE (1/n)Σ(ŷ-y)²:

  • dL/dw = (2/n) Σ(ŷ-y)x
  • dL/db = (2/n) Σ(ŷ-y).

Batch GD: all examples per update (stable, full-batch costly). SGD: one random example/update (noisy, fast updates). Mini-batch: 32/64/128 examples (common compromise). Features at very different scales make optimization slower/less stable; standardization helps. For very high learning rate loss oscillates/diverges; tiny rate learns slowly.

import numpy as np
X = np.array([1.,2.,3.,4.,5.]); y = 2*X + 1
w, b, lr = 0., 0., 0.02
for epoch in range(1000):
    error = (w*X+b)-y
    dw = 2*np.mean(error * X)
    db = 2*np.mean(error)
    w -= lr*dw
    b -= lr*db
print('trained w,b', round(w,3), round(b,3))

flowchart TD
    A[Initialize parameters] --> B[Forward: predict]
    B --> C[Compute loss]
    C --> D[Compute gradient]
    D --> E[Update weights]
    E --> F{Converged / max epochs?}
    F -- No --> B
    F -- Yes --> G[Evaluate on held-out data]

Debug: Plot loss per epoch; NaN indicates overflow/invalid data/high rate; gradient zeros can signal convergence or bad feature/implementation. Lab: labs/06_gradient_descent.py records loss and saves a plot. Interview: Why mini-batch? More efficient updates vs full batch, less noisy than one-sample SGD.

13. Regression Diagnostics, Regularization & Bias-Variance

Underfitting vs overfitting

High bias / underfit: model too simple; both train/validation error high. High variance / overfit: training error low, validation high; likely learned noise/memorization. Complexity, dataset size, feature selection, cross-validation, regularization change balance.

Linear regression assumptions for common inference: approximately linear conditional mean, independence, sufficiently constant error variance for conventional standard errors, low problematic multicollinearity, exogeneity to interpret coefficients; normally distributed residuals primarily matters for certain small-sample inference, not basic point predictions. Diagnostic plots help, don't blindly trust textbook assumptions.

  • Ridge (L2) adds α Σw² penalty → shrinks coefficients, usually retains them.
  • Lasso (L1) adds α Σ|w| → can make coefficients exactly zero (selection).
  • Elastic Net mixes L1+L2 useful for correlated/high-dimensional features.
  • α tune using cross-validation, train-only pipeline.
  • Multicollinearity highly correlated predictors make individual coefficients unstable; VIF as diagnostic, regularization helps prediction.
from sklearn.linear_model import Ridge, Lasso, ElasticNet
ridge = Ridge(alpha=1.0)
lasso = Lasso(alpha=0.1, max_iter=10000)
model = ElasticNet(alpha=0.05, l1_ratio=0.5, max_iter=10000)

flowchart TD
    A[Compare train and validation error] --> B{Both high?}
    B -- Yes --> C[Underfit: enrich features / capacity]
    B -- No --> D{Train low, validation high?}
    D -- Yes --> E[Overfit: regularize / more data]
    D -- No --> F[Proceed to error analysis]

Interview: Why L1 sparse? L1 has corners in constraint geometry and nondifferentiability at zero, often optimum at a zero coefficient. Practice: Compare Ridge/Lasso on correlated inputs and record zero coefficients, train CV error.

14. Feature Engineering, Missing Values, Encoding, Selection

Feature engineering vs selection

Engineering converts raw data into meaningful predictors (timestamp -> day_of_week, amount/unit, customer transactions last month). Selection picks subset of columns to control noise, compute cost, multicollinearity. Filter (variance, mutual information), wrapper (recursive feature elimination), embedded (Lasso, tree-based) are main families.

Preprocessing workflow (leakage-safe)

flowchart TD
    A[Raw dataset] --> B[Train/test split]
    B --> C[Fit imputer / scaler / encoder on TRAIN]
    C --> D[Train estimator on transformed TRAIN]
    D --> E[Apply saved transformers to TEST]
    E --> F[Evaluate on TEST]
    F --> G[Save full pipeline, not model alone]

Missing numeric: median imputation simple; categorical: most frequent / constant 'unknown'. Missing indicator may help. Scaling: StandardScaler mean=0/std=1 by training statistics; tree models usually don't need feature scaling, distance/regularized linear models usually do. Encoding: one-hot for unordered nominal categories; ordinal encoding only if natural order or model handles it properly. Class imbalance: metrics matter; never SMOTE/oversample before splitting (leakage).

from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.pipeline import Pipeline
num = Pipeline([('fill', SimpleImputer(strategy='median')),
                ('scale', StandardScaler())])
cat = Pipeline([('fill', SimpleImputer(strategy='most_frequent')),
                ('onehot', OneHotEncoder(handle_unknown='ignore'))])
pre = ColumnTransformer([('num', num, ['age','income']),
                         ('cat', cat, ['city'])])

Pitfall: Future feature like “days until loan default” cannot be used to predict default at issue time; target encoding folds incorrectly leaks target. Lab: labs/07_pipeline_regression.py includes ColumnTransformer + Pipeline + cross-validation.

15. Classification: KNN, Logistic Regression, Naive Bayes, SVM

Binary classification

Output classes 0/1; often model yields score/probability, threshold makes decision. Spam vs ham, fraud vs genuine. Class priors, probability calibration, false-positive/false-negative costs guide threshold.

Model Main idea Strength Watch out
KNN nearby examples vote intuitive nonlinear distance scaling, slow prediction, dimensionality
Logistic regression sigmoid of linear score interpretable baseline linear boundary, scaling, regularization
Naive Bayes Bayes + conditional feature independence fast, text/counts good independence assumption, calibration
SVM maximize separation margin; kernels add nonlinear boundaries strong medium-size datasets scaling, hyperparameters, costly large data

KNN distance: Euclidean √Σ(xᵢ−zᵢ)²; if income in lakhs and age in years, income can dominate distance unless scaled. k small high variance; k large smoothing/high bias.

Logistic regression: p(y=1|x)=σ(w·x+b). Fit commonly minimizes log loss, not MSE. threshold=0.5 is default, not necessarily business-optimal.

Naive Bayes: P(class|features) ∝ P(class)∏P(feature_i|class) under conditional independence model. MultinomialNB useful bag-of-words counts.

SVM: seeks separating hyperplane with margin; C trades violations vs regularization; gamma RBF kernel reach; both tune CV. Very large C can overfit.

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
classifier = make_pipeline(StandardScaler(), SVC(kernel='rbf', C=1, gamma='scale'))

flowchart LR
    A[Input example] --> B[Preprocessing]
    B --> C[Classification score]
    C --> D{Score >= chosen threshold?}
    D -- Yes --> E[Positive]
    D -- No --> F[Negative]
    E --> G[Compare outcome with ground truth]
    F --> G

Lab: labs/08_classification_metrics.py compares logistic, KNN, NB and SVM on synthetic small data; compute confusion matrix and score. Interview: Why PR-AUC often better in rare positives? It focuses on precision vs recall for positive class; ROC-AUC may appear high even with many false positives at large negative-class scale.

16. Decision Trees, Random Forest, Gradient Boosting, XGBoost

Tree

Tree repeatedly splits a feature based on impurity reduction (Gini, entropy for classification; squared error for regression). Leaf outputs class/probability/mean. Depth unlimited → often overfit. Use max_depth, min_samples_leaf, pruning (ccp_alpha).

Bagging: bootstrap samples → multiple models trained in parallel → average/vote reduces variance. Random Forest: bagging trees plus random feature subsets at splits → decorrelate trees; strong tabular baseline. Boosting: new weak model sequentially corrects ensemble error/gradient direction (Gradient Boosting). XGBoost: optimized gradient boosted trees with regularization and engineering features; not the same thing as random forest.

flowchart TD
    A[Training data] --> B1[Bootstrap sample 1]
    A --> B2[Bootstrap sample 2]
    A --> B3[Bootstrap sample 3]
    B1 --> T1[Tree 1]
    B2 --> T2[Tree 2]
    B3 --> T3[Tree 3]
    T1 --> C[Average / majority vote]
    T2 --> C
    T3 --> C

from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
rf = RandomForestClassifier(n_estimators=120, max_depth=6, random_state=42, n_jobs=1)
gb = HistGradientBoostingClassifier(max_iter=100, learning_rate=0.08,
                                    max_leaf_nodes=15, random_state=42)

Diagnostics: Feature importance from impurities can be biased toward high-cardinality features; permutation importance on held-out data helps but correlated features complicate attribution. Gradient Boosting too many iterations + high learning rate may overfit; early stopping helps. Practice: Train tree vs RF, compare cross-validation scores and feature importance stability. Interview: Bagging vs boosting? Parallel bootstrap aggregation vs sequential error reduction.

17. PCA, Clustering, Dimensionality Reduction

Unsupervised learning

Labels ke bina underlying patterns dekhna. K-Means groups points into k clusters minimizing within-cluster squared distance; iterate centroid assignment → centroid update. Initialization matters; standardized features often required; spherical/compact clusters assumption common. Choose k via domain knowledge, silhouette, elbow (heuristic; no universal optimum).

PCA orthogonal directions with maximum sample variance; typical sequence: training split → scale if units differ → PCA.fit(train) → transform train/test. PCA components linear combinations, often less interpretable. PCA is not “feature selection” in the original-feature sense; it is feature extraction.

DBSCAN: density-based clusters + noise; no explicit cluster count, but eps, min_samples sensitive to scale/density. Hierarchical clustering: merges/splits clusters, dendrogram visualization; choice of linkage/distance matters.

flowchart TD
    A[Unlabeled numerical data] --> B[Impute + scale]
    B --> C{Goal?}
    C -- Reduce dimensions --> D[PCA]
    C -- Find groups --> E[KMeans / DBSCAN / Hierarchical]
    D --> F[Visualize / feature compression]
    E --> G[Check quality / business meaning]

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.cluster import KMeans
pca = make_pipeline(StandardScaler(), PCA(n_components=2, random_state=42))
clusters = make_pipeline(StandardScaler(), KMeans(n_clusters=3, n_init=10, random_state=42))

Pitfalls: Applying PCA before train split leaks distribution; K-Means with categorical data without encoding misrepresents distances; clusters are not ground-truth identities. Lab: labs/09_clustering_pca.py saves a PCA visualization.

18. Evaluation: Cross-Validation, Metrics, Tuning, Leakage

Confusion matrix

Predicted positive Predicted negative
Actual positive TP FN
Actual negative FP TN

Precision=TP/(TP+FP) among predicted positives how many correct; Recall=TP/(TP+FN) among actual positives how many caught; F1=2PR/(P+R) when denominator nonzero. Accuracy (TP+TN)/all, misleading when 99.5% majority class. ROC-AUC measures ranking over thresholds; PR-AUC/AP suits rare positive focus. Calibration: prediction 0.8 should correspond to ~80% positives among similar predictions, approximately.

Cross-validation: k-fold rotates validation folds; stratified k-fold preserves proportions for classification; group k-fold prevents group leakage; TimeSeriesSplit respects sequence (with suitable gap where needed). Tuning with CV picks hyperparameters; separate holdout remains final.

flowchart TD
    A[Split: training / final test] --> B[CV folds on training only]
    B --> C[Fit preprocessing and model inside each fold]
    C --> D[Select hyperparameters]
    D --> E[Refit best pipeline on entire training]
    E --> F[Evaluate exactly once on final test]
    F --> G[Document errors, uncertainty and limitations]

from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
# scores = cross_val_score(clf, X_train, y_train, cv=cv, scoring='f1')

Interviews: CV score not same as final holdout; nested CV useful for less biased estimate of full model-selection process. Lab: labs/07_pipeline_regression.py and labs/08_classification_metrics.py.

Must-answer interview questions

  1. Data Analyst vs Data Scientist? Analyst typically asks/describes business signals; scientist additionally may develop predictive/statistical models and experiments. Roles overlap.
  2. DataFrame vs NumPy array? Labeled heterogeneous columns vs primarily homogeneous numerical n-dimensional arrays.
  3. Bias vs variance? Consistent systematic error vs sensitivity to different training samples.
  4. What is leakage? Info unavailable at prediction time or evaluation contamination unintentionally enters training pipeline.
  5. ROC-AUC vs accuracy? ROC-AUC ranking across thresholds; accuracy one chosen threshold and class mix.
  6. p-value interpretation? Null-assumption extremeness, not probability null true.
  7. L1 vs L2? L1 sparsity/selection often, L2 smooth shrinkage.
  8. Bagging vs boosting? Bootstrap parallel variance reduction vs sequential fitted corrections.
  9. Why standardize? Similar scales stabilize distance/optimization-based models; trees generally less sensitive.
  10. Why train/test separation? Unbiased-ish estimate of generalization to unseen data under representative split.
  11. PCA vs feature selection? PCA creates combinations; selection retains original variables.
  12. Why monitor after deploy? Data/behavior change, dependencies fail, real outcomes may worsen.
