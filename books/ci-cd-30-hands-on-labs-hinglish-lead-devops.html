1. Prerequisites and setup

Debian 12 terminal: git, python3, python3-venv, curl, jq; for later labs: Jenkins, Java supported by your Jenkins release, Docker Engine, Terraform, AWS CLI v2, kubectl, Helm, oc, and optionally Argo CD CLI. Install each from its official maintained instructions, pin tested versions, and confirm with --version before running labs. Windows/.NET labs require a Windows build agent with supported .NET SDK, NuGet feeds and test runner. Scanner labs require installed scanner binaries. Don't execute a Windows PowerShell command in Debian Bash.

sudo apt update
sudo apt install -y git curl jq python3 python3-venv python3-pip
mkdir -p ~/cicd-masterclass && cd ~/cicd-masterclass
git init
python3 -m venv .venv
. .venv/bin/activate
pip install flask pytest pytest-cov gunicorn

Cost and security: EKS, EC2, NAT gateways, ALBs, RDS, hosted runners, scanners and registries can cost money. Set an AWS Budget alert; use isolated test accounts and short-lived credentials. Restrict IAM privileges, avoid publicly exposing Jenkins/SonarQube, and remove resources after each cloud lab. terraform destroy only affects resources tracked in the selected state and does not guarantee all billable items are removed. Never paste real credentials into source code, build logs or chat.

2. Runnable starter project

Create these files in ~/cicd-masterclass. The app intentionally stays simple so pipeline behavior is the focus.

app.py

from flask import Flask, jsonify
app = Flask(__name__)

@app.get('/health')
def health():
    return jsonify(status='ok'), 200

@app.get('/')
def index():
    return jsonify(message='CI/CD masterclass'), 200

if __name__ == '__main__':
    app.run(host='127.0.0.1', port=5000)

test_app.py

from app import app

def test_health():
    response = app.test_client().get('/health')
    assert response.status_code == 200
    assert response.json['status'] == 'ok'

requirements.txt

flask>=3,<4
gunicorn>=22,<24

Dockerfile

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt && useradd --create-home appuser
COPY app.py .
USER appuser
EXPOSE 5000
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "app:app"]

python app.py & APP_PID=$!

kill "$APP_PID"

Command workflow: pytest imports the Flask app → creates an in-process HTTP test client → invokes /health → asserts status and JSON. curl checks the real local HTTP listener. Tests failing means stop before building/deploying.

4. Reference implementations

4.1 Jenkinsfile — runnable Python quality and Docker build pipeline

Requires Jenkins agents labeled docker with Python 3, Docker access and appropriate agent permissions. Do not mount the Docker socket into untrusted workloads. Configure registry credentials in Jenkins Credentials store; do not store them in the repository. The example builds and tests locally and does not push to a registry automatically.

pipeline {
  agent { label 'docker' }
  options { timestamps(); timeout(time: 20, unit: 'MINUTES'); disableConcurrentBuilds() }
  stages {
    stage('Checkout') { steps { checkout scm } }
    stage('Unit tests') {
      steps {
        sh '''
          set -eu
          python3 -m venv .venv
          . .venv/bin/activate
          pip install -r requirements.txt pytest pytest-cov
          python -m pytest -q --junitxml=test-results.xml
        '''
      }
      post { always { junit allowEmptyResults: true, testResults: 'test-results.xml' } }
    }
    stage('Build image') {
      steps { sh 'docker build -t cicd-flask:${BUILD_NUMBER} .' }
    }
    stage('Smoke test') {
      steps {
        sh '''
          set -eu
          docker run -d --name "cicd-smoke-${BUILD_NUMBER}" -p 127.0.0.1:0:5000 "cicd-flask:${BUILD_NUMBER}"
          PORT=$(docker port "cicd-smoke-${BUILD_NUMBER}" 5000/tcp | awk -F: '{print $NF}')
          i=0
          until curl -fsS "http://127.0.0.1:${PORT}/health"; do
            i=$((i+1)); [ "$i" -lt 20 ] || exit 1; sleep 1
          done
        '''
      }
      post { always { sh 'docker rm -f "cicd-smoke-${BUILD_NUMBER}" || true' } }
    }
  }
  post { always { cleanWs() } }
}

Line-by-line workflow: agent selects a Docker-capable worker; options enforce timeouts and serial execution; checkout pins source to build revision; Python venv isolates dependencies; JUnit archives test results; Docker creates the immutable image for that build number; smoke test runs a temporary container and checks HTTP readiness; post removes the temporary container and workspace. Production improvement: use an isolated agent, digest-pinned base image, vulnerability gates, registry push with OIDC/short-lived credentials, signature verification, environment approval and progressive rollout.

4.5 Terraform pipeline policy

PR: terraform fmt -check → terraform init -backend=false (syntax/provider setup only) → terraform validate → static analysis → reviewed plan using configured backend and read credentials. Main branch: require approval and fresh reviewed plan, enforce remote state locking, use short-lived IAM identity, apply once, capture outputs, verify service health. Do not publish a plan file openly: it may contain sensitive values. Never auto-apply untrusted pull requests.
