2.6 Process

A process is a running program.

View processes:

ps aux

or:

ps -ef

Example:

root       1     0  ... /sbin/init
www-data 845     1  ... nginx

2.7 PID

PID means:

Process ID

Example:

nginx PID = 845

Find a process:

ps -ef | grep nginx

2.8 PPID

PPID means:

Parent Process ID

Example:

PID  = 845
PPID = 1

The parent-child relationship helps explain process trees.

Use:

pstree

2.9 Signals

Signals communicate events to processes.

Common examples:

SIGTERM
SIGKILL
SIGHUP
SIGINT

Graceful termination:

kill <PID>

This normally sends:

SIGTERM

Force kill:

kill -9 <PID>

This sends:

SIGKILL

Do not default to kill -9.

Give applications a chance to shut down cleanly when possible.

2.10 systemd

Many modern Linux distributions use systemd.

Check service:

systemctl status ssh

or on some distributions:

systemctl status sshd

Start:

sudo systemctl start ssh

Enable at boot:

sudo systemctl enable ssh

Restart:

sudo systemctl restart ssh

2.11 Service Troubleshooting

Use:

systemctl status <service>

Then:

journalctl -u <service>

Recent logs:

journalctl -u <service> -n 100

Follow logs:

journalctl -u <service> -f

2.32 Routing Table

Linux:

ip route

Example:

default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0

2.33 Longest Prefix Match

When multiple routes match a destination, routers prefer the most specific matching prefix.

Example:

10.0.0.0/8
10.10.0.0/16
10.10.20.0/24

Destination:

10.10.20.5

Most specific:

10.10.20.0/24

This principle is essential for AWS route tables.

2.34 MAC Address

A MAC address identifies a network interface at Layer 2.

View:

Example:

52:54:00:12:34:56

2.35 ARP

ARP resolves IPv4 addresses to Layer-2 MAC addresses on a local network.

Concept:

Host A knows:

IP = 192.168.1.20

Needs:

MAC = ?

ARP discovers the mapping.

View neighbor table:

ip neigh

2.39 UDP

UDP is connectionless.

It has lower protocol overhead but does not provide TCP's built-in reliability guarantees.

Common use cases include:

DNS queries
Streaming
Telemetry
Real-time traffic

depending on application design.

2.95 Troubleshooting the Workflow

If DNS fails:

Application may be healthy
but user cannot resolve name.

If TCP fails:

DNS may be correct
but port/network path is unavailable.

If TLS fails:

TCP may work
but certificate/handshake is invalid.

If HTTP returns 500:

Network may work
but application has failed.

2.109 Interview Questions — Linux

Q1. Process vs service?

A process is a running program.

A service is a long-running system function/application often managed by a service manager such as systemd.

Q2. SIGTERM vs SIGKILL?

SIGTERM asks a process to terminate and can be handled.

SIGKILL immediately terminates and cannot be caught or ignored by the target process.

Q3. How do you find a listening port?

ss -lntp

2.110 Interview Questions — Networking

Q4. What is a default gateway?

A router used for destinations not matched by a more specific route.

Q5. TCP vs UDP?

TCP is connection-oriented and provides reliability/order mechanisms.

UDP is connectionless with lower protocol overhead and no built-in TCP-style reliability.

Q6. What is DNS?

DNS maps domain names to records such as IP addresses and other service information.

2.112 Interview Questions — YAML

Q8. Why is YAML important in Kubernetes?

Kubernetes resource manifests are commonly defined in YAML.

Q9. What determines YAML hierarchy?

Indentation.

Q10. YAML vs JSON?

Both represent structured data. YAML is generally more human-friendly; JSON is widely used by APIs and machine interfaces.
